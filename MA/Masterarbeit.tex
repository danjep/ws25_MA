\section{Introduction}\label{sec:intro}
Almost every computer that is in use today provides multiple simultaneously running processors to satisfy the surging demand for computational power. In order to reap the benefits that multiple processors provide, developers have to design their programs to use concurrently running threads. 
Since multiple threads may operate on the same memory, it is possible that on some memory location one thread writes a value that another thread wants to use, but never sees. In \Cref{fig:example} two threads each write a value on a memory location that the other one reads. 
Multiple different executions are possible: If thread $T_1$ is executed completely before $T_2$ the result is different to when $T_2$ is executed completely before $T_1$. The situation where two or more threads access the same memory space and at least one of them uses a write operation is called a \textit{data race}. This is what makes the different executions possible.\\

Every program that a thread might execute consists of instructions which in turn consist of memory accesses. The instruction \texttt{a=y} for example consists of two operations, reading the value of \texttt{y} and writing the read value to \texttt{a}. These two operations are usually called events.
CPU architectures and compilers may reorder the events in such programs for performance reasons and interleave the two threads as they see fit. 
Since this permits different executions for the same program, programmers need to be careful about their code. Programming languages and CPU architectures provide \textit{memory consistency models} (MCM) in order to give them some orientation about how their code will be handled by the compiler and hardware.
Since the language MCM determines the semantics of a program, developers need to confine themselves to the rules of the language (e.g. \textit{Data-Race-Freedom} (DRF)). In return they get certain guarantees for how the program will be compiled and executed. 
The memory consistency model of a CPU architecture describes how the hardware will behave if it runs the instructions of the compiled program. For the program to have the intended semantics, the code needs to be respect the rules of the language MCM and the compiled instructions have to be consistent with the hardware MCM. 
Essentially, the MCMs  determine which update to the shared memory is seen by which thread at what time.

As can be seen in the example, the memory consistency model can change the outcome of a program drastically. But the presence of a MCM may not guarantee the intended behavior. 
MCMs are defined by humans and can have bugs. They may not capture the behavior of the architecture correctly or be insufficiently defined.

\subsection{Memory Consistency Models}\label{sec:MCM}
Memory Consistency Models constitute what programmers and execution environments agree on when it comes to how concurrent programs are allowed to be executed. They define consistency constraints on execution graphs and provide guarantees for how memory accesses are processed on shared memory.
Memory models can roughly be divided into two classes, operational models and axiomatic ones.
Operational models are abstractions of real machines with idealized components and may be perceived as being more intuitive. 
Axiomatic models constrain relations on memory operations to allow or disallow behavior of programs. To this end one can understand memory operations as nodes in a graph where the edges are relations between these operations like the \textit{program order} (\po) or \textit{read-from} (\rf).
While \po{} describes the order of instructions within a single thread, \rf{} depicts for each read which write provides the value that is extracted. \\
Therefore the \po{} relation is given by how the program is written and \rf{} depends on the execution.
From this, one can deduce that there are multiple possible execution graphs. In \Cref{fig:examplegraph,fig:storebuffering} one can see the possible graphs of the example from \Cref{fig:example}.

Since simulation \cite{Mad+10} and verification \cite{Alg+13} are substantially faster on axiomatic models, research has focused on this type. 
Axiomatic models are defined in three stages: mapping each instruction onto a mathematical object and defining relations on the events, constructing a set of candidate executions like in \Cref{fig:examplegraph,fig:storebuffering} and deciding which executions are valid according to the constraints on the relations. \\
They are typically expressed in the CAT language of \cite{Alg+14} which covers all of relational algebra and established itself as a standard. More on the CAT language in \Cref{sec:cat}.\\
To validate that a program is executed according to a given MCM is called \textit{consistency checking} and can be reduced to a certain depth-first search on the execution graph \cite{Kok+23}. A program is consistent with a model if it fulfills all constraints of the model. \\
For consistency checking there exist many automated tools like HERD \cite{Alg+14}, GenMC \cite{KokVaf21} and Dartagnan \cite{Pon+18}. 
The issue this master's thesis deals with is verification of memory consistency models which is a very different problem. According to \cite{Gru+26} it consists of five tasks that an automated verification tool should ideally cover:
The first task is to check generic properties of MCMs like permitting no out-of-thin-air values. The second task is to review properties referring to operation's semantics like \textit{barrier monotonicity} (there are fewer possible executions when inserting synchronizations). The next task is to compare models and determine which is stronger. Task four is to create litmus tests that check whether a language or architecture implements a model. The last task is to verify compiler transformations. \\
Since we want to verify the models and not a program, it is important to check properties for every program that could be executed under the model.
For this task there exist two automated tools, KATER \cite{Kok+23} and RAT \cite{Gru+26} which both are not able to handle every possible MCM but only a fragment.

The most intuitive and restrictive MCM is Lamport's \textit{Sequential Consistency} (SC) \cite{Lam79} which guarantees that operations are executed as if they were in some sequential order and the operations of each thread follow \po .
Later, models that are less restrictive like \textit{SC per Location} (also known as \textit{Coherence} or \textit{UNIPROC}) and \textit{Total Store Order} (TSO)\cite{SPA92} were developed to allow for more optimization by the hardware.




\subsection{The CAT language} \label{sec:cat}

In 2014 Alglave et al. proposed an axiomatic framework for modelling weak memory and the corresponding language CAT \cite{Alg+14} which has since then become the standard for writing axiomatic memory consistency models. In this case, weakness is defined as accepting a larger number of possible executions of a program than stronger models. 
The CAT language uses base sets which are the events of an execution. There are the set of all events $E$, the initial writes $IW$, all reads $R$, writes $W$ and fences $F$, the branch events $B$ and the memory events $M$ which are the reads and writes \cite{Alg+16}.
CAT has some built-in base relations which include the already mentioned \po{} and \rf. Besides those, there are the \textit{same location} relation \loc, which connects all events of one particular memory location, the \textit{external} relation \ext{} which includes all pairs of events that originate from different threads, the \textit{coherence order} \co{} which is a total order of writes on the same memory location, the \textit{read-modify-write} relation \rmw{} that relates a read event with a write event of the same memory location that can be interpreted as an atomic operation and the \textit{identity} and empty relations \texttt{id} and $0$. Furthermore it provides the constraints \texttt{acyclic}, \texttt{irreflexive} and \texttt{empty} which are sufficient for expressing every desired model and property. 

\begin{figure}[H]
\begin{align*}
\langle cat\rangle &:= \langle constraint\rangle \mid \langle cat \rangle~ \langle cat\rangle \\
\langle constraint \rangle &:= \texttt{acyclic } \langle rel \rangle \mid \texttt{irreflexive } \langle rel \rangle \mid \texttt{empty } \bangle{rel} \\

\bangle{base\_rel} &:= \textsf{po} \mid \text{\rf} \mid \textsf{rmw} \mid \co \mid \loc \mid \ext \mid \textsf{id} \mid \textsf{0} \\

\end{align*}

Furthermore, $\textsf{0}$ denotes the empty relation and \id~ the identity relation.}   
\label{fig:cat}
\end{figure}

Besides the given base relations, one can define derived relations in the CAT language like \textit{from-read} (\fr), connecting reads to those writes that occur after the write operation from which they read or \textit{happens-before} (\hb) which relates each event to the ones that occurred before \cite{Lam78}. The derivations can be written with the keyword \texttt{let} and using the operations in \Cref{fig:cat} like this:
\[\texttt{let } \fr = \text{\rf}^{-1}\text{.\co} \qquad \texttt{let } \text{\hb}=\textsf{po}\cup \text{\co}\cup \text{\rf} \cup \text{\fr}\]
The language also includes some base sets of events. These include the set of all events E, all reads (R) and writes (W), initial writes IW and fences F. \\
The Memory Models from the last section can be formalized according to \cite{Gru+26,Kou+24} like this:
\begin{align*}
&\text{(SC) } \hfill &\texttt{acyclic }\hb \\
&\text{(TSO) } \hfill &\texttt{irreflexive }(\po \setminus (W\times R) \cup (\rf \cap \textsf{ext}) \cup \co \cup \fr)^+ \\
&\text{(SC per Location)} \hfill &\texttt{acyclic } (\po \cap \loc) \cup (\rf \cup \co \cup \fr)
\end{align*}  


\section{Related Work}\label{sec:kontext}

There are currently several established lines of research in the field of weak memory. One obvious issue is the \textit{consistency checking} of programs under a given memory model \cite{Tun+23,KokVaf21}. Several automated tools that were developed in the last decade already handle this issue well. Examples are GenMC \cite{KokVaf21}, DARTAGNAN \cite{Pon+18} and HERD \cite{Alg+14}.
Furthermore, there is research on refining stateless model checking \cite{Jon+25}.
%In the realm of verification this would be on the program verification level. 
Some research groups instead examine the models themselves and their attributes \cite{LahBok22} and others the already mentioned operational models \cite{Ior+23,Doh+22}. Additionally, researchers are looking at ways of comparing \cite{Wic+17,Sha+23} and verifying \cite{Kok+23,And+25,Kir+20} memory consistency models which are closely related problems.

The first tool to verify MCMs was KATER \cite{Kok+23} which covered only a fragment of CAT that could be transformed into Kleene Algebra with Tests (KAT). This fragment excluded set difference, complement, intersections, converses and the construction of relations from sets. \\
Since a lot of MCMs like SC, TSO, Power and Arm8 could be defined without the use of these operations, KATER was already very useful and through the exclusion of complement and intersections the verification becomes PSAPCE-complete instead of EXPSPACE-complete \cite{KozSmi97,Nak17}.
Notably, the fragment of \cite{Kok+23} excludes the definitions of C11 and the Linux Kernel Memory Model (LKMM) \cite{Kou+24}. To include these models and others, intersections are needed.
The next year Koutsouridis et al. presented KATI \cite{Kou+24} which is able to handle converses and some intersections but was not implemented.

The first tool that addressed all intersections as well as inverses and construction of relations from sets (called rational CAT, see \Cref{fig:cat}) was RAT (Relational Algebra with Tableaus) which was developed by the supervisors of this master's thesis in 2025 \cite{Gru+26}. Their tool is able to handle the first four tasks of the verification with only the compiler transformations being left as an open issue. In their yet to be published work, they present a logical theory of relations where the unsatisfiability of a formula is equivalent to the model fulfilling a set of assertions.
By transforming the question of $\llbracket M\rrbracket \subseteq \semsof{M_{prop}}$ into $\semsof{M} \cap \overline{\semsof{M_{prop}}} = \emptyset$ and then a formula $ \psi_M \land \neg \psi_{M_{prop}}$ it proves whether the given model is stronger than the condition that is to be tested.
The formula is then decomposed until there exists a satisfying model for the formula or it is deemed unsatisfiable. 

Today there are many open questions in this field of research. Is it possible to automatically verify  more than the rational CAT fragment?
Can the popular models written in CAT be transformed into ones that are written in rational CAT?
Is it possible to verify compiler transformations?
This master's thesis will be about the issue of whether the proof system in \cite{Gru+26} can be improved while sustaining the soundness and completeness.

\subsubsection{Write and Read Restrictions} \label{sec:restrictions}
Let $W \subseteq E$ be the set of all write operations and $R \subseteq E$ the set of all read operations in the set of events. $[W]$ and $[R]$ denote the relations $W \times W \cap \id$ and $R \times R \cap \id$. These relations can be used to restrict other relations to write and read operations.
An example is $[W].\po .[R]$, which restricts \po{} to only those elements which feature a write as the first event and a read as the second one. One can use this notation for assumptions about the relations in the CAT language. For example, the \rf{} relation can always be assumed to be restricted to writes in the first position and reads in the second one, i.e. $[W].\rf .[R]$, since it relates writes to those reads which use the written data. \\
This notation is furthermore justified by the semantics of the CAT language, since the expression
\[[W].\rf .[R] := \{(w,r) \mid (w,w) \in [W] \land (w,r) \in \rf \land (r,r) \in [R]\}\]
allows only for entries that consist of a write and a read event. 
In \Cref{sec:relationspecific} we use this notation to represent the known restrictions on the base relations in the rules and in \Cref{sec:assumptions} to integrate assumptions that are defined in the CAT file.

\subsection{Executions}
Executions consist of a set of all events that occur $E_X$, the set of initial writes $IW_X$ and the base relations relations that are determined through the program and how it is executed. It is one possible instance of the relations on the memory events that describe how the code is run. The fact that executions consist of elements with relations between them, allows us to interpret them as execution graphs like the ones in \Cref{fig:examplegraph,fig:storebuffering}.
\begin{definition}[Execution]
An execution $X$ is the following tuple: \todo{brauchen wir die tiefgestellten X?}
\[X := (E_X, IW_X, \po_X , \rf_X, \rmw_X, \co_x, \loc_X, \ext_X , \id_X)\]  
where $\po_X, \rf_X, \rmw_X, \co_X, \loc_X, \ext_X, \id_X \subseteq E_X \times E_X$.
$\mathbb{E} = \mathbb{P}(X)$ denotes the set of all possible executions. \\
Furthermore, for any in CAT constructed relation $\bangle{rel}$, $\bangle{rel}_X$ denotes the instance of it on the execution $X$.
\end{definition}


\subsection{Semantics} \label{sec:semantics}
The semantics of a MCM $M$ can be defined along the definition of the CAT language. In general, they are the set of executions that the model allows. The semantics of relations is simply the set of elements in the relation.
\begin{definition}[Semantics] \label{def:sem}
Let $M$ be a memory consistency model, $\bangle{cat},\bangle{cat}_1,\bangle{cat}_2$ be CAT expressions and $\bangle{rel},\bangle{rel}_1,\bangle{rel}_2 \subseteq E \times E$ be relations. The semantics are defined as follows:
\begin{align*}
\semsof{M} & := \semsof{\bangle{cat}} \\
\semsof{\bangle{cat}_1~ \bangle{cat}_2} & := \semsof{\bangle{cat}_1} \cap \semsof{\bangle{cat}_2} \\
\semsof{\texttt{empty}~ \bangle{rel}} &:= \{X \in \E \mid \nexists (e_1,e_2) \in \semsof{\bangle{rel}_X}\} \\
\semsof{\texttt{irreflexive}~ \bangle{rel}} &:= \{X \in \E \mid \forall e \in E_X: \nexists (e,e) \in \semsof{\bangle{rel}_X} \} \\
\semsof{\texttt{acyclic}~ \bangle{rel}} &:= \semsof{\texttt{irreflexive}~ \bangle{rel}^+} \\
\semsof{\bangle{rel}_1 \subseteq \bangle{rel}_2} &:= \forall (e,e'):((e,e') \in \bangle{rel}_1 \impl (e,e') \in \bangle{rel}_2) \\
\semsof{\bangle{rel}_1.\bangle{rel}_2} &:= \{(e_1,e_2) \mid \exists (e_1,e') \in \semsof{\bangle{rel}_1} \land (e',e_2) \in \semsof{\bangle{rel}_2}\} \\
\semsof{\bangle{rel}_1 \cup \bangle{rel}_2} &:= \{(e,e') \in \semsof{\bangle{rel}_1} \lor (e,e') \in \semsof{\bangle{rel}_2} \} \\
\semsof{\bangle{rel}_1 \cap \bangle{rel}_2} &:= \{ (e,e') \in \semsof{\bangle{rel}_1} \land (e,e') \in \semsof{\bangle{rel}_2}\} \\
\semsof{\bangle{rel}_1 \setminus \bangle{rel}_2} &:= \{ (e,e') \in \semsof{\bangle{rel}_1} \land (e,e') \notin \semsof{\bangle{rel}_2}\} \\
\semsof{\sim \bangle{rel}} &:= \{(e_1,e_2) \mid (e_1,e_2) \notin \semsof{\bangle{rel}}\} \\
\semsof{\bangle{rel}^{-1}} &:= \{(e_1,e_2) \mid (e_2,e_1) \in \semsof{\bangle{rel}}\} \\
\semsof{\bangle{rel}^+} &:= \{(e,e') \mid \exists n \in \N: (e,e_1), \dots ,(e_n,e') \in \semsof{\bangle{rel}}\} \\
\semsof{\bangle{rel}?} &:= \semsof{\bangle{rel}} \cup \id \\
\semsof{\bangle{rel}^*} &:= \semsof{\bangle{rel}?} \cup \semsof{\bangle{rel}^+} \\
\semsof{\bangle{base\_set}_1 \times \bangle{base\_set}_2} &:= \{(e,e') \mid e \in \bangle{base\_set}_1, e' \in \bangle{base\_set}_2\} \\
\semsof{\bangle{base\_rel}} &:= \{ (e,e') \in \bangle{base\_rel} \}
\end{align*}
\end{definition}
For better readability, the \semsof{\cdot} symbols can be omitted when dealing with relations, since the semantics are equal to the intuitive definition of relations.

\section{The Proof System} \label{sec:proofsys}
In order to prove $\semsof{M} \subseteq \semsof{M_{prop}}$ we devise a general method of proving one model to be stronger than another based on inclusion between the relations. For this purpose, we design rules that the expression $\semsof{M} \subseteq \semsof{M'}$ from the statement $true$. The derivation therefore acts according to logical implication, since $true \impl \semsof{M} \subseteq \semsof{M'}$ would mean that the implied part holds. If there is no valid derivation from $true$ to the inclusion that should be proven, then the inclusion cannot hold.
Since there may be multiple branches of reasoning it is important to clarify that every branch needs to start at $true$ in order to verify the inclusion.
Additionally to the rules that model logical implications between relational terms, we need common transformations like commutativity of the unification, we need the definitions of derived relations that use only the base relations and we need rules to eliminate the constraints. 


\subsection{Basic Rules}
The most basic rules are those which are always true for any relations. We list them here and sort them by the contributing operators. For commutative operators like unification there is only one version of each rule since there is no different effect when interchanging the relations. Furthermore, in \Cref{sec:transformations} we state rules for commutativity and others. \\
Let $\Delta[t]$ be a relation term that includes the subterm $t$. 


\begin{itemize}
\item No operator:

\textcolor{red}{\inferrule*[left=(transitivity)]{\sf r \subseteq s \\ \rel{s} \subseteq \rel{t}}{\rel{r} \subseteq \rel{t}}} \and

\inferrule*[left=(weak)]{\Delta[\sf r] \subseteq s \\ \sf t \subseteq r}{\Delta[\sf t] \subseteq s} 
\end{mathpar}
\item Unification $\cup$
\begin{mathpar}
%\inferrule*[left=($\cup_{2R}$)]{\it true}{\sf r \subseteq r \cup s} \and durch (U3R) und (ref)
\inferrule*[left=($\cup_{2L}$)]{\sf r \subseteq s}{\sf r \cup s \subseteq s} \and
\textcolor{red}{\inferrule*[left=($\cup_{3R}$)]{\sf r \subseteq s}{\sf r \subseteq s \cup t}} \and
\end{mathpar}

\item Intersection $\cap$
\begin{mathpar}
\inferrule*[left=($\cap_{2L}$)]{\it true}{\sf r \cap s \subseteq r} \and

\end{mathpar}

\item Concatenation $.$

\textcolor{red}{

\inferrule*[left=($._{2Rr}$)]{\sf \id \subseteq s}{\sf r \subseteq r.s}} \and 
\textcolor{red}{\inferrule*[left=($._{2Lr}$)]{\sf r \subseteq \id}{\sf s.r \subseteq s} \and

\end{mathpar}

\subsection{Transformations}\label{sec:transformations}
Another part of the rules are transformations which are based on equalities of terms (e.g. $\sf r~ \cup~ s= s~ \cup~ r$) instead of inclusion between terms. Therefore, the transformations can be used in either direction and terms on either side of the inclusion can be replaced.
The set theoretic operators $\cup$ and $\cap$ have the properties of distributivity, associativity and commutativity. Concatenation is associative and distributive and commutative for two equal terms. 
\begin{definition}[Commutativity, Associativity, Distributivity]
Let $\circ$ and $\star$ be two operations on a set $S$ and $r,s \in S$.
\begin{eqnarray*}
\text{(Commutativity) }& r \circ s &= s \circ r \\
\text{(Associativity) }& r \circ (s \circ t) &= (r \circ s) \circ t \\
\text{(Distributivity) }& r \circ (s \star t) &= (r \circ s) \star (r \circ t)
\end{eqnarray*}
\end{definition}

To incorporate the capabilities these properties offer, they will be added to the set of rules here. For that purpose, let $\Gamma[t]$ be an inclusion term that contains the subterm $t$.

\begin{mathpar}
\inferrule*[left=($\cup_{comm}$)]{\Gamma[\sf r\cup s]}{\Gamma[\sf s \cup r]} \and
\inferrule*[left=($\cap_{comm}$)]{\Gamma[\sf r \cap s]}{\Gamma[\sf s \cap r]} \and
\inferrule*[left=($._{comm}$)]{\Gamma[\sf r.r^*]}{\Gamma[\sf r^*.r]} \and
\inferrule*[left=($\cup_{ass}$)]{\Gamma[\sf (r \cup s) \cup t]}{\Gamma[\sf r \cup (s \cup t)]} \and
\inferrule*[left=($\cap_{ass}$)]{\Gamma[\sf (r \cap s) \cap t]}{\Gamma[\sf r \cap (s \cap t)]} \and
\inferrule*[left=($\cup_{dist}$)]{\Gamma[\sf r \cup s \cup s']}{\Gamma[\sf r \cup (s \cup s')]} \and
\inferrule*[left=($\cap_{dist}$)]{\Gamma[\sf r \cap s \cap s']}{\Gamma[\sf r \cap (s \cap s')]} \and
\inferrule*[left=($\cup_{\cap dist}$)]{\Gamma[\sf r \cup (s \cap s')]}{\Gamma[\sf (r \cup s) \cap (r \cup s')]} \and
\inferrule*[left=($\cap_{\cup dist}$)]{\Gamma[\sf r \cap (s \cup s')]}{\Gamma[\sf (r \cap s) \cup (r \cap s')]} \and
\inferrule*[left=($._{\cup distR}$)]{\Gamma[\sf r.s \cup r.s']}{\Gamma[\sf r.(s \cup s')]} \and
\inferrule*[left=($._{\cup distL}$)]{\Gamma[\sf s.r \cup s'.r]}{\Gamma[\sf(s \cup s').r]} \and
\inferrule*[left=($._{\cap distR}$)]{\Gamma[\sf r.s \cap r.s']}{\Gamma[\sf r.(s \cap s')]} \and
\inferrule*[left=($._{\cap distL}$)]{\Gamma[\sf s.r \cap s'.r]}{\Gamma[\sf(s \cap s').r]} 
\end{mathpar}

The proof in \Cref{sec:inversionproof} provides the following rules for handling terms that include inversions:
\begin{mathpar}
\inferrule*[left=($-1_{\cup}$)]{\Gamma[\sf r^{-1} \cup s^{-1}]}{\Gamma[\sf (r \cup s)^{-1}]} \and
\inferrule*[left=($-1_{\cap}$)]{\Gamma[\sf r^{-1} \cap s^{-1}]}{\Gamma[\sf (r \cap s)^{-1}]} \and
\inferrule*[left=($-1_{.}$)]{\Gamma[\sf s^{-1}.r^{-1}]}{\Gamma[\sf (r.s)^{-1}]} \and
\inferrule*[left=($-1_{\sim}$)]{\Gamma[\sf \sim (r^{-1})]}{\Gamma[\sf (\sim r)^{-1}]} \and
\inferrule*[left=($-1_{+}$)]{\Gamma[\sf (r^{-1})^+]}{\Gamma[\sf (r^+)^{-1}]} \and
\inferrule*[left=($-1_{*}$)]{\Gamma[\sf (r^{-1})^*]}{\Gamma[\sf (r^*)^{-1}]} \and
\inferrule*[left=($-1_{?}$)]{\Gamma[\sf (r^{-1})?]}{\Gamma[\sf (r?)^{-1}]}
\end{mathpar}


The Kleene star $*$ and reflexive closure $?$ can be resolved into a term consisting of two subterms connected through a unification operator. Therefore we do not need explicit rules for these operators, but can rely on the rules for unification. 
There are still some transformations for these operators based on their definition:
\begin{mathpar}
\inferrule*[left=($+$)]{\Gamma[\sf r.r^*]}{\Gamma[\sf r^+]} \and
\inferrule*[left=($?$)]{\Gamma[\sf r \cup \id]}{\Gamma[\sf r?]} \and
\inferrule*[left=($*$)]{\Gamma[\sf \id \cup r^+]}{\Gamma[\sf r^*]} \and
\end{mathpar}

The following transformations may come in handy but are less straightforward. We will need to prove them. 
\begin{mathpar}
%\inferrule*[left=($+_{\cup}$)]{\Gamma[\sf r^+ \cup s^+]}{\Gamma[\sf (r^+ \cup s^+)^+]} \and nicht invertible
\inferrule*[left=($+_{\cap}$)]{\Gamma[\sf r^+ \cap s^+]}{\Gamma[\sf (r^+ \cap s^+)^+]} \and 
\inferrule*[left=($*_{\cup elim}$)]{\Gamma[\sf (r^*.s^*)^*]}{\Gamma[\sf (r \cup s)^*]} \and
\inferrule*[left=($*_{double}$)]{\Gamma[\sf r^*.r^*]}{\Gamma[\sf r^*]} 
\end{mathpar}
\begin{lemma}
Let \textsf{r,s} be relations. Then $\sf r^+ \cap s^+ = (r^+ \cap s^+)^+$ holds. 
\end{lemma}
\begin{proof}
\begin{eqnarray*}
(e,e') \in {\sf r^+ \cap s^+} &\Leftrightarrow & (e,e') \in {\sf r^+} \land (e,e') \in {\sf s^+} \\
&\Leftrightarrow & (e,e_1),\dots ,(e_n,e') \in {\sf r^+} \land (e,e_1),\dots,(e_n,e') \in \sf s^+ \\
&\Leftrightarrow & (e,e_1),\dots ,(e_n,e') \in {\sf (r^+ \cap s^+)} \\
&\Leftrightarrow & (e,e') \in {\sf (r^+ \cap s^+)^+}
\end{eqnarray*}
\end{proof}


\begin{lemma} Let {\sf r,s} be relations. Then $\sf (r^*.s^*)^* = (r \cup s)^*$ holds.
\end{lemma}
\begin{proof}
\begin{itemize}
\item[$\subseteq$:] For any $(e_1,e_h) \in \sf (r^*.s^*)^*$ there exist $k,m_1,\dots m_k,n_1,\dots n_k \in \N_0$ with $(e_1,e_h) \in {\sf r}^{m_1}.{\sf s}^{n_1}. \dots {\sf r}^{m_k}.{\sf s}^{n_k}$.
Consequently, there need to be $(e_1,e_{2}),\dots ,(e_{h-1},e_{h})$ where every $(e_i,e_{i+1})$ is either in \textsf{r} or \textsf{s} and $h = \sum_{j=1}^k m_j + n_j$.
Accordingly, $(e_1,e_h)$ is in $\sf (r \cup s)^h$ and thus $(e_1,e_h) \in \sf (r \cup s)^*$.
\item[$\supseteq$:] We can use other transformations to prove this direction.
\begin{eqnarray*}
\sf (r^*.s^*)^* &=& \sf (r^*.s^*)^+ \cup \id \\
&=& \sf ((r^+ \cup \id).(s^+ \cup \id))^+ \cup \id \\
&=& \sf (r^+.s^+ \cup r^+.\id \cup \id.s^+ \cup \id.\id)^+ \cup \id \\
&=& \sf (r^+.s^+ \cup r^+ \cup s^+ \cup \id)^+ \cup \id \\
&\supseteq & \sf (r \cup s)^+ \cup \id \\
&=& \sf (r \cup s)^*
\end{eqnarray*}
\end{itemize}
\end{proof}


\begin{lemma} Let {\sf r} be a relation. Then $\sf r^* = r^*.r^*$ holds. \end{lemma}
\begin{proof}
\begin{itemize}
\item[$\subseteq$:] For any $(e,e') \in \sf r^*$ it holds that $(e,e') \in \sf r^*.\id$ and hence $(e,e') \in \sf r^*.r^*$. \\
\item[$\supseteq$:] For any $(e,e') \in \sf r^*.r^*$ there exist $n,m \in \N_0$ with $(e,e') \in \sf r^n.r^m$. Since $\sf r^n.r^m$ is the same as ${\sf r}^{n+m}$, it holds that $(e,e') \in \sf r^{n+m}$ and therefore $(e,e') \in \sf r^*$.
\end{itemize}
\end{proof}

All of these rules are invertible and can be applied in reverse.

\subsection{Relation-specific Rules}\label{sec:relationspecific}
Memory Consistency Models are defined on a group of relations. Each of them comes with certain properties that need to be recognized in the rules. The empty relation \0{} functions as a neutral element for unification and absorbing element for concatenation and intersection, while the identity relation \id{} is a neutral element for concatenation.
\begin{mathpar}
\inferrule*[left=($\0_{\cup}$)]{\Gamma[\sf r]}{\Gamma[\sf \0 \cup r]} \and
\inferrule*[left=($\0_{\cap}$)]{\Gamma[\0]}{\Gamma[\sf r \cap \0]} \and
\inferrule*[left=($\0_{conc}$)]{\Gamma[\0]}{\Gamma[\sf r.\0.s]} \and
\inferrule*[left=($\text{id}_{conc}$)]{\Gamma[\sf r.s]}{\Gamma[\sf r.\id .s]} 
\end{mathpar}
The base relations \id, \loc{} and \ext{} are symmetric, meaning that for every $(e,e')$ in the relation, $(e',e)$ is in the relation too. For \po, \id, \co{} and \loc{} it holds that they are transitive, meaning for every $(e,e'),(e',e'') \in R: (e,e'') \in R$. Furthermore, any relation might be symmetric if it is included in \id. Hence, it is a generalization of the ($\text{ID}_{symm}$) rule.
\begin{mathpar}
\inferrule*[left=($\id_{symm}$)]{\it true}{\id^{-1} \subseteq \id} \and
\inferrule*[left=($\loc_{symm}$)]{\it true}{\loc^{-1} \subseteq \loc} \and
\inferrule*[left=($\ext_{symm}$)]{\it true}{\ext^{-1} \subseteq \ext} \and
\inferrule*[left=($\id_{trans}$)]{\true}{\id .\id \subseteq \id} \and
\inferrule*[left=($\po_{trans}$)]{\true}{\po .\po \subseteq \po} \and
\inferrule*[left=($\text{co}_{trans}$)]{\true}{\co .\co \subseteq \co} \and
\inferrule*[left=($\loc_{trans}$)]{\true}{\loc .\loc \subseteq \loc} \and
\inferrule*[left=($r_{symm}$)]{\Gamma[\sf r^{-1}] \\ \sf r \subseteq \id}{\Gamma[\sf r]} 
\end{mathpar}
As we have described in \Cref{sec:restrictions}, the relations \rel{[W]} and \rel{[R]} can be used to restrict relations to groups of events. Some base relations are already restricted. The \rf{} relation only connects writes to reads and the \co{} relation only connects writes to later writes.
Besides this we use some rules to handle \rel{[W]} and \rel{[R]} themselves.
\begin{mathpar}
\inferrule*[left=(W)]{\true}{\sf [W] \subseteq \id} \and
\inferrule*[left=(R)]{\true}{\sf [R] \subseteq \id} \and
\inferrule*[left=(WR)]{\true}{\sf [W].[R] \subseteq \0} \and
\inferrule*[left=(RW)]{\it true}{\sf [R].[W] \subseteq \0} \and
\inferrule*[left=(rf)]{\it true}{\sf \rf = [W].\rf .[R]} \and
\inferrule*[left=(co)]{\it true}{\sf \co = [W].\co .[W]} 
\end{mathpar}
The last part of relation-specific rules concerns inclusions between base relations like the one between \textsf{ppo} and \po. The inclusion between \rf{} and \loc{} is based on the fact, that \rf{} relates two events on the same memory location, namely one read and the write that provided the value in that location. Since \loc{} includes connections between all events on the same location, every entry of \rf{} needs to be in \loc{}. The same holds for the consecutive writes on the same location in \co{}. 
\begin{mathpar}
\inferrule*[left=(\textsf{ppo})]{\true}{\textsf{ppo} \subseteq \po} \and
%\inferrule*[left=(rf+)]{true}{\rf .\rf \subseteq \0} \and wegen (RW) überflüssig
\inferrule*[left=(\text{rfloc})]{\true}{\rf \subseteq \loc} \and
\inferrule*[left=(\text{coloc})]{\true}{\co \subseteq \loc} 
\end{mathpar}





\subsection{Eliminating the Constraints}
One important aspect that one has to keep in mind when comparing models is that the constraints \texttt{acyclic}, \texttt{irreflexive} and \texttt{empty} inverse the inclusion of relations.
This means the following:
\begin{lemma}
For any $\rel{r}_1 \subseteq \rel{r}_2$ it applies that $\bangle{constraint}~ \rel{r}_2 \subseteq \bangle{constraint}~ \rel{r}_1$ if the constraint is the same for each relation.
\end{lemma}
\begin{proof}
We can prove this for each of the constraints. 
Let the constraint be \texttt{empty}:
\begin{eqnarray*}
\sf r_1 \subseteq r_2 
& \impl &\forall X \in \E : (\nexists (e_1,e_2) \in {\sf r_2}_X \impl \nexists (e_1,e_2) \in {\sf r_1}_X) \\
& \impl &(X \in \semsof{\texttt{empty}~ \sf r_2} \impl X \in \semsof{\texttt{empty}~ \sf r_1}) \\
& \impl & \semsof{\texttt{empty}~ \sf r_2} \subseteq \semsof{\texttt{empty}~ \sf r_1}
\end{eqnarray*}

\noindent For the constraint \texttt{irreflexive}:
\begin{eqnarray*}
\sf r_1 \subseteq r_2 
& \impl &\forall X \in \E : (\forall e \in E_X: \nexists(e,e) \in {\sf r_2}_X \impl \forall e \in E_X: \nexists (e,e) \in {\sf r_1}_X) \\
& \impl &(X \in \semsof{\texttt{irreflexive}~ \sf r_2} \impl X \in \semsof{\texttt{irreflexive}~ \sf r_1}) \\
& \impl & \semsof{\texttt{irreflexive}~ \sf r_2} \subseteq \semsof{\texttt{irreflexive}~ \sf r_1}
\end{eqnarray*}

\noindent For the \texttt{acyclicity} constraint:
\begin{eqnarray*}
\sf r_1 \subseteq r_2 
& \impl &\forall X \in \E : (\forall e \in E_X: \nexists(e,e) \in {\sf r_2}_X^+ \impl \forall e \in E_X: \nexists (e,e) \in {\sf r_1}_X^+) \\
& \impl &(X \in \semsof{\texttt{acyclic}~ \sf r_2} \impl X \in \semsof{\texttt{acyclic}~ \sf r_1}) \\
& \impl & \semsof{\texttt{acyclic}~ \sf r_2} \subseteq \semsof{\texttt{acyclic}~ \sf r_1}
\end{eqnarray*}
\end{proof}
\noindent This lemma generates the following three rules:
\begin{mathpar} 
\inferrule*[left=(empty)] {\sf r_1 \subseteq r_2}{\sf \semsof{\texttt{empty}~ r_2} \subseteq \semsof{\sf \texttt{empty}~ r_1}} \and 
\inferrule*[left=(acyclic)] {\sf r_1 \subseteq r_2}{\sf \semsof{\texttt{acyclic}~ r_2} \subseteq \semsof{\texttt{acyclic}~ r_1}} \and
\inferrule*[left={(irreflexive)}] {\sf r_1 \subseteq r_2}{\sf \semsof{\texttt{irreflexive}~ r_2} \subseteq \semsof{\texttt{irreflexive}~ r_1}}
\end{mathpar}

Since not every inclusion offers the comfort of having both models use the same constraint, they need to be converted. For this purpose there are some rules:

\begin{lemma}\label{lem:irracy}
For a relation $R$, it holds that $\semsof{\texttt{irreflexive}~ R^+} = \semsof{\texttt{acyclic}~ R}$.
\end{lemma}
\begin{proof}
This is given via the \Cref{def:sem} of $\semsof{\texttt{acyclic}~ \bangle{rel}}$.
\end{proof}

\begin{lemma}\label{lem:emptyirr}
For any relation $\sf r$ it holds that $\semsof{\texttt{empty}~ \sf r} = \semsof{\texttt{irreflexive}~ \sf r.r^{-1}}$.
\end{lemma}
\begin{proof} This can equally be proven using \Cref{def:sem}.
\begin{eqnarray*}
\semsof{\texttt{empty}~ \sf r} &=& \{X \in \E \mid \nexists (e_1,e_2) \in \sf r_X\} \\
&=& \{X \in \E \mid \forall e \in E_X: \nexists (e,e') \in \sf r_X\} \\
&= & \{X \in \E \mid \forall e \in E_X: \nexists (e,e) \in \sf r_X.r_X^{-1} \} \\
&=& \semsof{\texttt{irreflexive}~ \sf r.r^{-1}}
\end{eqnarray*}
\end{proof}

\begin{lemma}\label{lem:emptyacy}
For any relation $\sf r$ it holds that $\semsof{\texttt{empty}~ \sf r} = \semsof{\texttt{acyclic}~ \sf r \cup r^{-1}}$.
\end{lemma}
\begin{proof}
\begin{eqnarray*}
\semsof{\texttt{empty}~ \sf r} &=& \{X \in \E \mid \nexists (e_1,e_2) \in \sf r_X\} \\
&=& \{X \in \E \mid \forall e \in E_X: \nexists (e,e') \in \sf r_X \} \\
&=& \{X \in \E \mid \forall e \in E_X: \nexists (e,e) \in \sf r_X \cup r_X^{-1} \} \\
&=& \semsof{\texttt{acyclic}~ \sf r \cup r^{-1}} \\
\end{eqnarray*}
\end{proof}

The \cref{lem:irracy,lem:emptyirr,lem:emptyacy} give us the following three rules:
\begin{mathpar}
\inferrule*[left=($a\rightarrow i$)]{\semsof{\texttt{irreflexive}~ \sf r^+}}{\semsof{\texttt{acyclic}~ \sf r}} \and
\inferrule*[left=($e \rightarrow i$)]{\semsof{\texttt{irreflexive}~ \sf r.r^{-1}}}{\semsof{\texttt{empty}~ \sf r}} \and
\inferrule*[left=($e \rightarrow a$)]{\semsof{\texttt{acyclic}~ \sf r\cup r^{-1}}}{\semsof{\texttt{empty}~ \sf r}}
\end{mathpar}
These will be needed to eliminate the constraint from the term.

\subsection{Incorporating the Assumptions and Definitions}\label{sec:assumptions}
In many CAT files the authors use derived relations and assumptions about these and the base relations that are not part of the initial assumptions given with CAT. The formulation is for example
\[ \texttt{assume r \& s = \0} \text{ or } \texttt{let r = (s | t)+}\]
for an assumption of an empty intersection between \rel{r} and \rel{s} and a definition of \rel{r} as the transitive closure of $\sf s \cup t$. \\
These definitions and assumptions can be incorporated into the proof system by transforming them into rules or by replacing the relations with the corresponding definitions and assumptions in preprocessing. To avoid producing extraordinary long terms, we use the former method.
Assumptions can easily be turned into axioms of the proof system. 

For an assumption \texttt{assume r <= s} we construct the rule 
\begin{mathpar}

%\end{mathpar}

We use definitions like \texttt{let r = s} as a rule

\inferrule*[left=(def)]{\Gamma[\sf s]}{\Gamma[\sf r]}
\end{mathpar}

\section{Completeness}
To prove the completeness on the rational CAT fragment of this proof system we will transform every proof from \cite{Gru+26}, where completeness was proven, into one of ours.  
The approach of \cite{Gru+26} transforms an inclusion of the form $\bangle{cat}_1 \subseteq \bangle{cat}_2$ into a logical formula $\varphi_{\neg \bangle{cat}_2} \land \varphi_{\bangle{cat}_1}$ where the unsatisfiability of the formula corresponds to the inclusion term being true.
Hence, the Theorem to be proven is this:
\begin{theorem}
If a RAT-CAT formula $\varphi_r \land \varphi_{\neg s}$ is $\mathcal{T}_\Sigma$-unsatisfiable, then there exists a proof  for $\sf r \subseteq s$
\end{theorem}

\section{Proof of the Inversion lemma}\label{sec:inversionproof}
\Cref{lem:inversion}:
Let $\bangle{cat}$ be a CAT expression that features an inversion. There is an expression $\bangle{cat} '$ that only features inversions that are applied to base relations with $\semsof{\bangle{cat}} = \semsof{\bangle{cat} '}$. \\
\begin{proof}
When it can be shown for each operation in CAT that the inversion of the whole expression can be passed on to the individual terms, any CAT expression has this property. Therefore we show the property for each operation.
\begin{align*}
\semsof{(R \cup S)^{-1}} &=& \{(e,e') \mid (e',e) \in R \cup S\} \\
&=& \{(e,e') \mid (e',e) \in R\} \cup \{(e,e') \mid (e',e) \in R\} \\
&=& \semsof{R^{-1}} \cup \semsof{S^{-1}} \\
&=& \semsof{R^{-1} \cup S^{-1}}
\end{align*}
\begin{align*}
\semsof{(R \cap S)^{-1}} &=& \{(e,e') \mid (e',e) \in R\cap S\} \\
&=& \{(e,e') \mid (e',e) \in R\} \cap \{(e,e')\mid (e',e) \in S\} \\
&=& \semsof{R^{-1}} \cap \semsof{S^{-1}} \\
&=& \semsof{R^{-1} \cap S^{-1}}
\end{align*}
\begin{align*}
\semsof{(R.S)^{-1}} &=& \{(e,e'') \mid (e'',e) \in (R.S)\} \\
&=& \{(e,e'') \mid \exists e': (e'',e') \in R, (e',e) \in S \} \\
&=& \{(e,e'') \mid \exists e': (e',e'') \in R^{-1}, (e,e') \in S^{-1}\} \\
&=& \semsof{R^{-1}.S^{-1}}
\end{align*}
\begin{align*}
\semsof{(\sim R)^{-1}} &=& \{(e,e') \mid (e',e) \in~ \sim R\} \\
&=& \{(e,e') \mid (e',e) \notin R\} \\
&=& \{(e,e') \notin R^{-1}\} \\
&=& \semsof{\sim (R^{-1})}
\end{align*}
\begin{align*}
\semsof{(R^+)^{-1}} &=& \{(e,e') \mid (e',e) \in R^+\} \\
&=& \{(e,e') \mid \exists n \in \N: (e',e_1),\dots ,(e_n,e) \in R\} \\
&=& \{(e,e') \mid \exists n \in \N: (e,e_n),\dots ,(e_1,e') \in R^{-1}\} \\
&=& \semsof{(R^{-1})^+}
\end{align*}
\begin{align*}
\semsof{(R?)^{-1}} &=& \{(e,e') \mid (e',e) \in R?\} \\
&=& \{(e,e') \mid (e',e) \in R \cup \id \} \\
&=& \{(e,e') \in R^{-1} \cup \id^{-1}\} \\
&=& \{(e,e') \in R^{-1} \cup \id\} \\
&=& \{(e,e') \in (R^{-1})?\} \\
&=& \semsof{(R^{-1})?}
\end{align*}
\begin{align*}
\semsof{(R^*)^{-1}} &=& \{(e,e') \mid (e',e) \in \id \cup R^+\} \\
&=& \{(e,e') \mid (e',e) \in \id\} \cup \{(e,e') \mid (e',e) \in R^+\} \\
&=& \{(e,e') \in \id^{-1}\} \cup \{(e,e') \in (R^+)^{-1}\} \\
&=& \{(e,e') \in \id \cup (R^{-1})^+ \} \\
&=& \{(e,e') \in (R^{-1})^*\} \\
&=& \semsof{(R^{-1})^*}
\end{align*}
\end{proof}
