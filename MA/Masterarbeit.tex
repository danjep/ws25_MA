\section{Introduction}\label{sec:intro}
Almost every computer that is in use today provides multiple simultaneously running processors to satisfy the surging demand for computational power. In order to reap the benefits that multiple processors provide, developers have to design their programs to use concurrently running threads. 
Since multiple threads may operate on the same memory, it is possible that on some memory location one thread writes a value that another thread wants to use, but never sees. In \Cref{fig:example} two threads each write a value on a memory location that the other one reads. 
Multiple different executions are possible: If thread $T_1$ is executed completely before $T_2$ the result is different to when $T_2$ is executed completely before $T_1$. The situation where two or more threads access the same memory space and at least one of them uses a write operation is called a \textit{data race}. This is what makes the different executions possible.\\

Every program that a thread might execute consists of instructions which in turn consist of memory accesses. The instruction \texttt{a=y} for example consists of two operations, reading the value of \texttt{y} and writing the read value to \texttt{a}. These two operations are usually called events.
CPU architectures and compilers may reorder the events in such programs for performance reasons and interleave the two threads as they see fit. 
Since this permits different executions for the same program, programmers need to be careful about their code. Programming languages and CPU architectures provide \textit{memory consistency models} (MCM) in order to give them some orientation about how their code will be handled by the compiler and hardware.
Since the language MCM determines the semantics of a program, developers need to confine themselves to the rules of the language (e.g. \textit{Data-Race-Freedom} (DRF)). In return they get certain guarantees for how the program will be compiled and executed. 
The memory consistency model of a CPU architecture describes how the hardware will behave if it runs the instructions of the compiled program. For the program to have the intended semantics, the code needs to be respect the rules of the language MCM and the compiled instructions have to be consistent with the hardware MCM. 
Essentially, the MCMs  determine which update to the shared memory is seen by which thread at what time.

As can be seen in the example, the memory consistency model can change the outcome of a program drastically. But the presence of a MCM may not guarantee the intended behavior. 
MCMs are defined by humans and can have bugs. They may not capture the behavior of the architecture correctly or be insufficiently defined.

\subsection{Memory Consistency Models}\label{sec:MCM}
Memory Consistency Models constitute what programmers and execution environments agree on when it comes to how concurrent programs are allowed to be executed. They define consistency constraints on execution graphs and provide guarantees for how memory accesses are processed on shared memory.
Memory models can roughly be divided into two classes, operational models and axiomatic ones.
Operational models are abstractions of real machines with idealized components and may be perceived as being more intuitive. 
Axiomatic models constrain relations on memory operations to allow or disallow behavior of programs. To this end one can understand memory operations as nodes in a graph where the edges are relations between these operations like the \textit{program order} (\po) or \textit{read-from} (\rf).
While \po{} describes the order of instructions within a single thread, \rf{} depicts for each read which write provides the value that is extracted. \\
Therefore the \po{} relation is given by how the program is written and \rf{} depends on the execution.
From this, one can deduce that there are multiple possible execution graphs. In \Cref{fig:examplegraph,fig:storebuffering} one can see the possible graphs of the example from \Cref{fig:example}.

Since simulation \cite{Mad+10} and verification \cite{Alg+13} are substantially faster on axiomatic models, research has focused on this type. 
Axiomatic models are defined in three stages: Map each instruction onto a mathematical object and defining relations on the events. Then, enumerate all candidate executions like in \Cref{fig:examplegraph,fig:storebuffering}. Finally, decide which executions are valid according to the constraints on the relations. \\
They are typically expressed in the CAT language of Alglave et al. \cite{Alg+14} which covers all of relational algebra and established itself as a standard. More on the CAT language in \Cref{sec:cat}.\\
To validate that a program is executed according to a given MCM is called \textit{consistency checking} and can be reduced to a certain depth-first search on the execution graph \cite{Kok+23}. A program is consistent with a model if it fulfills all constraints of the model. \\
For consistency checking there exist many automated tools like HERD \cite{Alg+14}, GenMC \cite{KokVaf21} and Dartagnan \cite{Pon+18}. 
The issue this master's thesis deals with is verification of memory consistency models which is a very different problem. According to Grünke et al. \cite{Gru+26} it consists of five tasks that an automated verification tool should ideally cover:
The first task is to check generic properties of MCMs like permitting no out-of-thin-air values. The second task is to review properties referring to operation's semantics like \textit{barrier monotonicity} (there are fewer possible executions when inserting synchronizations). The next task is to compare models and determine which is stronger. Task four is to create litmus tests that check whether a language or architecture implements a model. The last task is to verify compiler transformations. \\
Since we want to verify the models and not a program, it is important to check properties for every program that could be executed under the model.
For this task there exist two automated tools, KATER \cite{Kok+23} and RAT \cite{Gru+26} which both are not able to handle every possible MCM but only a fragment.

The most intuitive and restrictive MCM is Lamport's \textit{Sequential Consistency} (SC) \cite{Lam79} which guarantees that operations are executed as if they were in some sequential order and the operations of each thread follow \po .
Later, models that are less restrictive like \textit{SC per Location} (also known as \textit{Coherence} or \textit{UNIPROC}) and \textit{Total Store Order} (TSO)\cite{SPA92} were developed to allow for more optimization by the hardware.




\subsection{The CAT language} \label{sec:cat}

In 2014 Alglave et al. proposed an axiomatic framework for modelling weak memory and the corresponding language CAT \cite{Alg+14} which has since then become the standard for writing axiomatic memory consistency models. In this case, weakness is defined as accepting a larger number of possible executions of a program than stronger models. 
The CAT language uses base sets which are the events of an execution. There are the set of all events $E$, the initial writes $IW$, all reads $R$, writes $W$ and fences $F$, the branch events $B$ and the memory events $M$ which are the reads and writes \cite{Alg+16}.
CAT has some built-in base relations which include the already mentioned \po{} and \rf. Besides those, there are the \textit{same location} relation \loc, which connects all events of one particular memory location, the \textit{external} relation \ext{} which includes all pairs of events that originate from different threads, the \textit{coherence order} \co{} which is a total order of writes on the same memory location, the \textit{read-modify-write} relation \rmw{} that relates a read event with a write event of the same memory location that can be interpreted as an atomic operation and the \textit{identity} and empty relations \texttt{id} and $0$. Furthermore it provides the constraints \texttt{acyclic}, \texttt{irreflexive} and \texttt{empty} which are sufficient for expressing every desired model and property. 

\begin{figure}[H]
\begin{align*}
\langle cat\rangle &:= \langle constraint\rangle \mid \langle cat \rangle~ \langle cat\rangle \\
\langle constraint \rangle &:= \texttt{acyclic } \langle rel \rangle \mid \texttt{irreflexive } \langle rel \rangle \mid \texttt{empty } \bangle{rel} \\
\langle rel \rangle &:= \langle base\_rel \rangle \mid \langle rel \rangle . \bangle{rel} \mid \bangle{rel}^* \mid \bangle{rel} \cup \bangle{rel} \mid \bangle{rel} \cap \bangle{rel} \\ &\quad \mid \bangle{rel}^{-1} \mid \bangle{rel}^+ \mid \bangle{rel}? \mid \bangle{base\_set} \times \bangle{base\_set} \mid \textcolor{teal}{\bangle{rel}\setminus \bangle{rel} \mid{} \sim\bangle{rel}} \\
\bangle{base\_rel} &:= \textsf{po} \mid \text{\rf} \mid \textsf{rmw} \mid \co \mid \loc \mid \ext \mid \textsf{id} \mid \textsf{0} \\
\bangle{base\_set} &:= \text{R} \mid \text{W} \mid \text{F} \mid \text{B} \mid \text{M} \mid \text{IW} \mid \text{E}
\end{align*}
\caption{The CAT language according to \cite{Alg+16}, where $\bangle{rel}^+$ is the transitive closure, $\bangle{rel}?$ the reflexive closure, $\bangle{rel}^*$ the reflexive and transitive closure, $\sim\bangle{rel}$ the complement. Furthermore, $\textsf{0}$ denotes the empty relation and \id~ the identity relation. \\
The \textcolor{teal}{teal}-colored part is what differentiates CAT from rational CAT.}   
\label{fig:cat}
\end{figure}

Besides the given base relations, one can define derived relations in the CAT language like \textit{from-read} (\fr), connecting reads to those writes that occur after the write operation from which they read or \textit{happens-before} (\hb) which relates each event to the ones that occurred before \cite{Lam78}. The derivations can be written with the keyword \texttt{let} and using the operations in \Cref{fig:cat} like this:
\[\texttt{let } \fr = \text{\rf}^{-1}\text{.\co} \qquad \texttt{let } \text{\hb}=\textsf{po}\cup \text{\co}\cup \text{\rf} \cup \text{\fr}\]
The language also includes some base sets of events. These include the set of all events E, all reads (R) and writes (W), initial writes IW and fences F. \\
The Memory Models from the last section can be formalized according to \cite{Gru+26,Kou+24} like this:
\begin{align*}
&\text{(SC) } \hfill &\texttt{acyclic }\hb \\
&\text{(TSO) } \hfill &\texttt{irreflexive }(\po \setminus (W\times R) \cup (\rf \cap \textsf{ext}) \cup \co \cup \fr)^+ \\
&\text{(SC per Location)} \hfill &\texttt{acyclic } (\po \cap \loc) \cup (\rf \cup \co \cup \fr)
\end{align*}

There are currently several established lines of research in the field of weak memory. One obvious issue is the \textit{consistency checking} of programs under a given memory model \cite{Tun+23,KokVaf21}. Several automated tools that were developed in the last decade already handle this issue well. Examples are GenMC \cite{KokVaf21}, DARTAGNAN \cite{Pon+18} and HERD \cite{Alg+14}.
Furthermore, there is research on refining stateless model checking \cite{Jon+25}.
%In the realm of verification this would be on the program verification level. 
Some research groups instead examine the models themselves and their attributes \cite{LahBok22} and others the already mentioned operational models \cite{Ior+23,Doh+22}. Additionally, researchers are looking at ways of comparing \cite{Wic+17,Sha+23} and verifying \cite{Kok+23,And+25,Kir+20} memory consistency models which are closely related problems.

The first tool to verify MCMs was KATER \cite{Kok+23} which covered only a fragment of CAT that could be transformed into Kleene Algebra with Tests (KAT). This fragment excluded set difference, complement, intersections, converses and the construction of relations from sets. \\
Since a lot of MCMs like SC, TSO, Power and Arm8 could be defined without the use of these operations, KATER was already very useful and through the exclusion of complement and intersections the verification becomes PSAPCE-complete instead of EXPSPACE-complete \cite{KozSmi97,Nak17}.
Notably, the fragment of \cite{Kok+23} excludes the definitions of C11 and the Linux Kernel Memory Model (LKMM) \cite{Kou+24}. To include these models and others, intersections are needed.
The next year Koutsouridis et al. presented KATI \cite{Kou+24} which is able to handle converses and some intersections but was not implemented.

The first tool that addressed all intersections as well as inverses and construction of relations from sets (called rational CAT, see \Cref{fig:cat}) was RAT (Relational Algebra with Tableaus) which was developed by the supervisors of this master's thesis in 2025 \cite{Gru+26}. Their tool is able to handle the first four tasks of the verification with only the compiler transformations being left as an open issue. In their yet to be published work, they present a logical theory of relations where the unsatisfiability of a formula is equivalent to the model fulfilling a set of assertions.
By transforming the question of $\llbracket M\rrbracket \subseteq \semsof{M_{prop}}$ into $\semsof{M} \cap \overline{\semsof{M_{prop}}} = \emptyset$ and then a formula $ \phi_M \land \neg \phi_{M_{prop}}$ it proves whether the given model is stronger than the condition that is to be tested.
The formula is then decomposed until there exists a satisfying model for the formula or it is deemed unsatisfiable. 

Today there are many open questions in this field of research. Is it possible to automatically verify  more than the rational CAT fragment?
Can the popular models written in CAT be transformed into ones that are written in rational CAT?
Is it possible to verify compiler transformations?
This master's thesis will be about the issue of whether the proof system in \cite{Gru+26} can be improved while sustaining the soundness and completeness.

\section{Preliminaries} \label{sec:preliminaries}

\subsection{Executions}
Executions consist of a set of all events that occur $E$, the set of initial writes $IW$ and the base relations relations that are determined through the program and how it is executed. It is one possible instance of the relations on the memory events that describe how the code is run. The fact that executions consist of elements with relations between them, allows us to interpret them as execution graphs like the ones in \Cref{fig:examplegraph,fig:storebuffering}.
\begin{definition}[Execution]
An execution $X$ is the following tuple:
\[X := (E, IW, \po, \rf, \rmw, \co, \loc, \ext, \id)\]  
where $\po, \rf, \rmw, \co, \loc, \ext, \id \subseteq E \times E$.
$\mathbb{E}$ denotes the set of all possible executions. 
%Furthermore, for any in CAT constructed relation $\bangle{rel}$, $\bangle{rel}_X$ denotes the instance of it on the execution $X$.
\end{definition}


\subsection{Semantics} \label{sec:semantics}
The semantics of a MCM $M$ can be defined along the definition of the CAT language. In general, they are the set of executions that the model allows. The semantics of relations is simply the set of elements in the relation.
\begin{definition}[Semantics of CAT Expressions] \label{def:catsem}
Let $M$ be a memory consistency model, $\bangle{cat}_1,\bangle{cat}_2$ be CAT expressions and\\ $\bangle{rel} \subseteq (E \times E)$ be a relation. The semantics of the CAT expressions are sets of executions and defined as follows:
\begin{align*}
\semsof{\bangle{cat}_1~ \bangle{cat}_2} & := \semsof{\bangle{cat}_1} \cap \semsof{\bangle{cat}_2} \\
\semsof{\texttt{empty}~ \bangle{rel}} &:= \{X \in \E \mid \nexists (e_1,e_2) \in \semsof{\bangle{rel}}\} \\
\semsof{\texttt{irreflexive}~ \bangle{rel}} &:= \{X \in \E \mid \forall e \in E: (e,e) \notin \semsof{\bangle{rel}} \} \\
\semsof{\texttt{acyclic}~ \bangle{rel}} &:= \semsof{\texttt{irreflexive}~ \bangle{rel}^+}
\end{align*} 
\end{definition}
For the relational subterms of the CAT expressions, the semantics differ in the regard that they are sets of edges in the execution graphs.
\begin{definition}[Semantics of Relational Expressions] \label{def:sem}
Let $\rel, \rel_1, \rel_2 \subseteq (E \times E)$ be relations. $\bangle{base\_rel}$ and $\bangle{base\_set}$ are as defined in \Cref{fig:cat}.
\begin{align*}
\semsof{\bangle{rel}_1 \subseteq \bangle{rel}_2} &:= \forall (e,e'):(e,e') \in \bangle{rel}_1 \impl (e,e') \in \bangle{rel}_2 \\
\semsof{\bangle{rel}_1.\bangle{rel}_2} &:= \{(e_1,e_2) \mid \exists (e_1,e') \in \semsof{\bangle{rel}_1} \land (e',e_2) \in \semsof{\bangle{rel}_2}\} \\
\semsof{\bangle{rel}_1 \cup \bangle{rel}_2} &:= \{(e,e') \in \semsof{\bangle{rel}_1} \lor (e,e') \in \semsof{\bangle{rel}_2} \} \\
\semsof{\bangle{rel}_1 \cap \bangle{rel}_2} &:= \{ (e,e') \in \semsof{\bangle{rel}_1} \land (e,e') \in \semsof{\bangle{rel}_2}\} \\
\semsof{\bangle{rel}_1 \setminus \bangle{rel}_2} &:= \{ (e,e') \in \semsof{\bangle{rel}_1} \land (e,e') \notin \semsof{\bangle{rel}_2}\} \\
\semsof{\sim \bangle{rel}} &:= \{(e_1,e_2) \mid (e_1,e_2) \notin \semsof{\bangle{rel}}\} \\
\semsof{\bangle{rel}^{-1}} &:= \{(e_1,e_2) \mid (e_2,e_1) \in \semsof{\bangle{rel}}\} \\
\semsof{\bangle{rel}^+} &:= \{(e,e') \mid \exists n \in \N: e = e_1 \land e'=e_n \land \forall i\in [1,n]: (e_i,e_{i+1}) \in \semsof{\bangle{rel}}\} \\
\semsof{\bangle{rel}?} &:= \semsof{\bangle{rel}} \cup \id \\
\semsof{\bangle{rel}^*} &:= \semsof{\bangle{rel}?} \cup \semsof{\bangle{rel}^+} \\
\semsof{\bangle{base\_set}_1 \times \bangle{base\_set}_2} &:= \{(e,e') \mid e \in \bangle{base\_set}_1, e' \in \bangle{base\_set}_2\} \\
\semsof{\bangle{base\_rel}} &:= \{ (e,e') \in \bangle{base\_rel} \}
\end{align*}
\end{definition}
To give a clear understanding of what the base relations are, we give definitions that are derived from those in Alglave et al. \cite{Alg+16,Alg+14}.
\begin{definition}[Semantics of Base Relations]
Let $E$ be the set of all events, $R$ the set of all read operations and $W$ the set of all write operations.
\begin{align*}
\semsof{\0} &:= \emptyset \times \emptyset \\
\semsof{\id} &:= \{(e,e) \mid e \in E\} \\
\semsof{\po} &:= \{\edgein E\times E \mid e \text{ and } e' \text{ belong to the same thread and } e \text{ happens before } e'\} \\
\semsof{\loc} &:= \{\edgein E\times E \mid e \text{ and } e' \text{ are on the same memory location}\} \\
\semsof{\ext} &:= \{\edgein E\times E \mid e \text{ and } e' \text{ belong to different threads}\} \\
\semsof{\rf} &:= \{\edgein W \times R \mid e \text{ is the last write before } e' \text{ on the same memory location}\} \\
\semsof{\co} &:= \{\edgein W\times W \mid e' \text{ happens after } e \text{ on the same memory location}\} \\
\semsof{\rmw} &:= \{\edgein R \times W \mid e' \text{ is the next event after the read } e \text{ in the program order } \po\}
\end{align*}
\end{definition}
For better readability, the \semsof{\cdot} symbols can be omitted when dealing with relations, since the semantics are equal to the intuitive definition of relations.


\subsection{Notation}
\paragraph{Abbreviation for Concatenation}
Let $\relr \subseteq (E \times E)$ be a relation. For any term where \relr~ is concatenated with itself $n \in \N$ times, we can instead write $\relr^n$. In this notation, $\relr$ is equal to $\relr^1$. This notation will shorten terms and increases readability. Furthermore, it yields a definition of the semantics of $\rel^+$ that is equivalent to the one in \Cref{def:sem}:
\begin{definition}[Alternative Definition of the Transitive Closure] \label{def:alttc}
Let $\rel \subseteq (E\times E)$ be a relation.
\[\semsof{\bangle{rel}^+} := \{(e,e') \mid \exists n \in \N: \edgein \bangle{rel}^n\] \end{definition}

\paragraph{Write and Read Restrictions} \label{sec:restrictions}
Let $W \subseteq E$ be the set of all write operations and $R \subseteq E$ the set of all read operations in the set of events. $[W]$ and $[R]$ denote the relations $(W \times W) \cap \id$ and $(R \times R) \cap \id$. These relations can be used to restrict other relations to write and read operations.
An example is $[W].\po .[R]$, which restricts \po{} to only those elements which feature a write as the first event and a read as the second one. One can use this notation for assumptions about the relations in the CAT language. For example, the \rf{} relation can always be assumed to be restricted to writes in the first position and reads in the second one, i.e. $[W].\rf .[R]$, since it relates writes to those reads which use the written data. \\
This notation is furthermore justified by the semantics of the CAT language, since the expression
\[[W].\rf .[R] := \{(w,r) \mid (w,w) \in [W] \land (w,r) \in \rf \land (r,r) \in [R]\}\]
allows only for entries that consist of a write and a read event. 
In \Cref{sec:relationspecific} we use this notation to represent the known restrictions on the base relations in the rules and in \Cref{sec:assumptions} to integrate assumptions that are defined in the CAT file.

\section{The Proof System} \label{sec:proofsys}
In order to prove $\semsof{M} \subseteq \semsof{M_{prop}}$ we devise a general method of proving one model to be stronger than another based on inclusion between the relations. For this purpose, we design rules that derive the expression $\semsof{M} \subseteq \semsof{M'}$ from the statement $\true$. The derivation therefore acts according to logical implication, since $\true \impl \semsof{M} \subseteq \semsof{M'}$ would mean that the implied part holds. If there is no valid derivation from $\true$ to the inclusion that should be proven, then the inclusion cannot hold.
Since there may be multiple branches of reasoning it is important to clarify that every branch needs to end at \true{} in order to verify the inclusion. We call a branch that ends in \true{} \textit{closed} and one that does not \textit{open}. Correspondingly, we call a derivation tree \textit{closed} if every branch is closed and \textit{open} otherwise.

\begin{definition}[CAT Inclusion Proofs]
Let $M,M'$ be CAT expressions constituting sets of executions on a domain of events $E$. A CAT Inclusion Proof $\prf^{CAT}$ is a closed derivation tree that starts at the bottom with $\semsof{M} \subseteq \semsof{M'}$ and ends at potentially several axioms using the rules from this section.
Hence, the proof derives the implication $\true \impl \semsof{M} \subseteq \semsof{M'}$.
\end{definition}

These proofs need rules to handle the CAT constraints which are given in the next subsection (\Cref{sec:constraints}). 

When the constraints are eliminated, all that is left is a relational inclusion term.  We can then apply transformations (\Cref{sec:transformations}) and relational implications (\Cref{sec:implications}) on the relational terms. By transformations we mean rules that are based on equivalences like the commutativity of unification and intersection. With the rules of the mentioned two subsections we can construct a \textit{Relational Inclusion Proof} $\prf$ for this inclusion term which is part of the CAT Inclusion Proof $\prf^{CAT}$.

\begin{definition}[Relational Inclusion Proofs]
Let $\relr,\rels \subseteq (E \times E)$ be two relations on a domain $E$. A Relational Inclusion Proof $\prf$ for the inclusion $\relr \subseteq \rels$ is a closed derivation tree that starts with the inclusion at the root and ends at potentially several leafs with \true{} using the rules in \Cref{sec:implications,sec:transformations}. The proof derives the implication $\true \impl \relr \subseteq \rels$. 
\end{definition}
This is the core element of the proof system. Putting the memory consistency models aside, this part of the rules allows us to prove any inclusion of relations that is universally true, like for example $a^* \subseteq (aa)^* \cup a(aa)^*$. \todo{Übergang} \\ 

Since this proof system is designed to handle CAT expressions and not just arbitrary relations, there are rules to capture the properties of the CAT base relations given in \Cref{sec:relationspecific}. Furthermore, there is a need to incorporate assumptions about the base relations and definitions of derived relations into the rules. We show this in \Cref{sec:assumptions}.


\subsection{Eliminating the Constraints}\label{sec:constraints}
One important aspect that one has to keep in mind when comparing models is that the constraints \texttt{acyclic}, \texttt{irreflexive} and \texttt{empty} inverse the inclusion of relations.
This means the following:
\begin{lemma}
For any $\relr_1 \subseteq \relr_2$ it applies that $\bangle{constraint}~ \relr_2 \subseteq \bangle{constraint}~ \relr_1$ if the constraint is the same for each relation.
\end{lemma}
\begin{proof}
We can prove this for each of the constraints. 
Let the constraint be \texttt{empty}:
\begin{eqnarray*}
\sf r_1 \subseteq r_2 
& \impl &\forall X \in \E : (\nexists (e_1,e_2) \in {\sf r_2} \impl \nexists (e_1,e_2) \in {\sf r_1}) \\
& \impl &(X \in \semsof{\texttt{empty}~ \relr_2} \impl X \in \semsof{\texttt{empty}~ \sf r_1}) \\
& \impl & \semsof{\texttt{empty}~ \sf r_2} \subseteq \semsof{\texttt{empty}~ \sf r_1}
\end{eqnarray*}

\noindent For the constraint \texttt{irreflexive}:
\begin{eqnarray*}
\sf r_1 \subseteq r_2 
& \impl &\forall X \in \E : (\forall e \in E: \nexists(e,e) \in {\sf r_2} \impl \forall e \in E_X: \nexists (e,e) \in {\sf r_1}) \\
& \impl &(X \in \semsof{\texttt{irreflexive}~ \relr_2} \impl X \in \semsof{\texttt{irreflexive}~ \sf r_1}) \\
& \impl & \semsof{\texttt{irreflexive}~ \sf r_2} \subseteq \semsof{\texttt{irreflexive}~ \sf r_1}
\end{eqnarray*}

\noindent For the \texttt{acyclicity} constraint:
\begin{eqnarray*}
\sf r_1 \subseteq r_2 
& \impl &\forall X \in \E : (\forall e \in E: \nexists(e,e) \in {\sf r_2}^+ \impl \forall e \in E_X: \nexists (e,e) \in {\sf r_1}^+) \\
& \impl &(X \in \semsof{\texttt{acyclic}~ \relr_2} \impl X \in \semsof{\texttt{acyclic}~ \sf r_1}) \\
& \impl & \semsof{\texttt{acyclic}~ \sf r_2} \subseteq \semsof{\texttt{acyclic}~ \sf r_1}
\end{eqnarray*}
\end{proof}
\noindent This lemma generates the following three rules:
\begin{rules}{Restraint Elimination} 
\inferrule*[left=(empty)] {\sf r_1 \subseteq r_2}{\sf \semsof{\texttt{empty}~ r_2} \subseteq \semsof{\sf \texttt{empty}~ r_1}} \and 
\inferrule*[left=(acyclic)] {\sf r_1 \subseteq r_2}{\sf \semsof{\texttt{acyclic}~ r_2} \subseteq \semsof{\texttt{acyclic}~ r_1}} \and
\inferrule*[left={(irreflexive)}] {\sf r_1 \subseteq r_2}{\sf \semsof{\texttt{irreflexive}~ r_2} \subseteq \semsof{\texttt{irreflexive}~ r_1}}
\end{rules}

Since not every inclusion offers the comfort of having both models use the same constraint, they need to be converted. For this purpose there are some rules:

\begin{lemma}\label{lem:irracy}
For a relation $R$, it holds that $\semsof{\mathtt{irreflexive}~ \relr^+} = \semsof{\mathtt{acyclic}~ \sf r}$.
\end{lemma}
\begin{proof}
This is given via the semantics of $\semsof{\mathtt{acyclic}~ \bangle{rel}}$ in \Cref{def:catsem}.
\end{proof}

\begin{lemma}\label{lem:emptyirr}
For any relation $\sf r$ it holds that $\semsof{\mathtt{empty}~ \sf r} = \semsof{\mathtt{irreflexive}~ \sf r.r^{-1}}$.
\end{lemma}
\begin{proof} This can equally be proven using \Cref{def:catsem}.
\begin{eqnarray*}
\semsof{\texttt{empty}~ \sf r} &=& \{X \in \E \mid \nexists (e_1,e_2) \in \sf r\} \\
&=& \{X \in \E \mid \forall e \in E: \nexists (e,e') \in \sf r\} \\
&= & \{X \in \E \mid \forall e \in E: \nexists (e,e) \in \sf r.r^{-1} \} \\
&=& \semsof{\texttt{irreflexive}~ \sf r.r^{-1}}
\end{eqnarray*}
\end{proof}

\begin{lemma}\label{lem:irrempty}
For any relation \relr it holds that $\semsof{\mathtt{irreflexive}~ \sf r} = \semsof{\mathtt{empty}~ \relr \cap \id}$.
\end{lemma}
\begin{proof}
\begin{eqnarray*}
\semsof{\texttt{irreflexive } \relr} &=& \{X \in \E \mid \forall e \in E: (e,e) \notin \relr\} \\
&=& \{X \in \E \mid \forall e \in E: (e,e) \notin \sf r \cap \id\} \\
&=& \{X \in \E \mid \nexists (e,e') \in \sf r \cap \id\} \\
&=& \semsof{\texttt{empty } \sf r \cap \id} 
\end{eqnarray*}
\end{proof}

\begin{lemma}\label{lem:emptyacy}
For any relation $\sf r$ it holds that $\semsof{\mathtt{empty}~ \sf r} = \semsof{\mathtt{acyclic}~ \sf r \cup r^{-1}}$.
\end{lemma}
\begin{proof}
\begin{eqnarray*}
\semsof{\texttt{empty}~ \sf r} &=& \{X \in \E \mid \nexists (e_1,e_2) \in \sf r\} \\
&=& \{X \in \E \mid \forall e \in E: \nexists (e,e') \in \sf r \} \\
&=& \{X \in \E \mid \forall e \in E: \nexists (e,e) \in \sf r \cup r^{-1} \} \\
&=& \semsof{\texttt{acyclic}~ \sf r \cup r^{-1}} \\
\end{eqnarray*}
\end{proof}

The \cref{lem:irracy,lem:emptyirr,lem:irrempty,lem:emptyacy} give us the following four rules:
\begin{rules}{Constraint Transformation}
\inferrule*[left=($a\rightarrow i$)]{\semsof{\texttt{irreflexive}~ \sf r^+}}{\semsof{\texttt{acyclic}~ \sf r}} \and
\inferrule*[left=($e \rightarrow i$)]{\semsof{\texttt{irreflexive}~ \sf r.r^{-1}}}{\semsof{\texttt{empty}~ \sf r}} \and
\inferrule*[left=($i \rightarrow e$)]{\semsof{\texttt{empty}~ \sf r \cap \id}}{\semsof{\texttt{irreflexive}~ \sf r}} \and
\inferrule*[left=($e \rightarrow a$)]{\semsof{\texttt{acyclic}~ \sf r\cup r^{-1}}}{\semsof{\texttt{empty}~ \sf r}}
\end{rules} 

These will be needed to eliminate the constraint from the term and to be able to continue with a relational inclusion proof.

\subsection{Transformations}\label{sec:transformations}
Another part of the rules are transformations which are based on equalities of terms (e.g. $\relr~ \cup~ \rels= \rels~ \cup~ \relr$) instead of inclusion between terms. Therefore, the transformations can be used in either direction and terms on either side of the inclusion can be replaced.

The empty relation \0{} functions as a neutral element for unification and absorbing element for concatenation and intersection, while the the full relation $(E \times E)$ is the neutral element for the intersection and the identity relation \id{} the neutral element for concatenation. This means, additionally, that \id{} is symmetric and transitive. Since this holds for any subrelation of \id{}, we can give generalizations of those rules for any relation \relr.
\begin{rules}{Neutral and Absorbing Element}
\inferrule*[left=($\0_{\cup}$)]{\Gamma[\sf r]}{\Gamma[\sf \0 \cup r]} \and
\inferrule*[left=($\0_{\cap}$)]{\Gamma[\0]}{\Gamma[\sf r \cap \0]} \and
\inferrule*[left=($\0_{conc}$)]{\Gamma[\0]}{\Gamma[\sf r.\0.s]} \and
\inferrule*[left=($\textsc{full}_\cap$)]{\Gamma[\relr]}{\Gamma[(E \times E) \cap \relr]} \and
\inferrule*[left=($\id_{conc}$)]{\Gamma[\sf r.s]}{\Gamma[\sf r.\id .s]} \and
%\inferrule*[left=($\id_{symm}$)]{\it true}{\id^{-1} \subseteq \id} \and
%\inferrule*[left=($\id_{trans}$)]{\true}{\id .\id \subseteq \id} \and
\inferrule*[left=($\relr_{symm}$)]{\Gamma[\relr^{-1}] \\ \relr \subseteq \id}{\Gamma[\relr]} \and
\inferrule*[left=($\relr_{trans}$)]{\Gamma[\relr] \\ \relr \subseteq \id}{\Gamma[\relr.\relr]} 
\end{rules}

The set theoretic operators $\cup$ and $\cap$ have the properties of distributivity, associativity and commutativity. Concatenation is associative and distributive.
\begin{definition}[Commutativity, Associativity, Distributivity]
Let $\circ$ and $\star$ be two operations on a set $S$ and $r,s \in S$.
\begin{eqnarray*}
\text{(Commutativity) }& r \circ s &= s \circ r \\
\text{(Associativity) }& r \circ (s \circ t) &= (r \circ s) \circ t \\
\text{(Distributivity) }& r \circ (s \star t) &= (r \circ s) \star (r \circ t)
\end{eqnarray*}
\end{definition}

To incorporate the capabilities these properties offer, they will be added to the set of rules here. For that purpose, let $\Gamma[t]$ be an inclusion term that contains the subterm $t$.

\begin{rules}{Operator Properties}
\inferrule*[left=($\cup_{comm}$)]{\Gamma[\sf r\cup s]}{\Gamma[\sf s \cup r]} \and
\inferrule*[left=($\cap_{comm}$)]{\Gamma[\sf r \cap s]}{\Gamma[\sf s \cap r]} \and
\inferrule*[left=($\cup_{ass}$)]{\Gamma[\sf (r \cup s) \cup t]}{\Gamma[\sf r \cup (s \cup t)]} \and
\inferrule*[left=($\cap_{ass}$)]{\Gamma[\sf (r \cap s) \cap t]}{\Gamma[\sf r \cap (s \cap t)]} \and
\inferrule*[left=($\cup_{dist}$)]{\Gamma[\sf r \cup s \cup s']}{\Gamma[\sf r \cup (s \cup s')]} \and
\inferrule*[left=($\cap_{dist}$)]{\Gamma[\sf r \cap s \cap s']}{\Gamma[\sf r \cap (s \cap s')]} \and
\inferrule*[left=($\cup_{\cap dist}$)]{\Gamma[\sf r \cup (s \cap s')]}{\Gamma[\sf (r \cup s) \cap (r \cup s')]} \and
\inferrule*[left=($\cap_{\cup dist}$)]{\Gamma[\sf r \cap (s \cup s')]}{\Gamma[\sf (r \cap s) \cup (r \cap s')]} \and
\inferrule*[left=($._{ass}$)]{\Gamma[\sf (r.s).t]}{\Gamma[\sf r.(s.t)]} \and
\inferrule*[left=($._{\cup distR}$)]{\Gamma[\sf r.s \cup r.s']}{\Gamma[\sf r.(s \cup s')]} \and
\inferrule*[left=($._{\cup distL}$)]{\Gamma[\sf s.r \cup s'.r]}{\Gamma[\sf(s \cup s').r]} \and
\inferrule*[left=($._{\cap distR}$)]{\Gamma[\sf r.s \cap r.s']}{\Gamma[\sf r.(s \cap s')]} \and
\inferrule*[left=($._{\cap distL}$)]{\Gamma[\sf s.r \cap s'.r]}{\Gamma[\sf(s \cap s').r]} 
\end{rules}

The Kleene star $*$ and reflexive closure $?$ can be resolved into a term consisting of two subterms connected through a unification operator. Therefore we do not need explicit rules for these operators, but can rely on the rules for unification. 
There are still some transformations for these operators based on their definition:
\begin{rules}{Operator Definitions}
\inferrule*[left=($+$)]{\Gamma[\sf r.r^*]}{\Gamma[\sf r^+]} \and
\inferrule*[left=($?$)]{\Gamma[\sf r \cup \id]}{\Gamma[\sf r?]} \and
\inferrule*[left=($*$)]{\Gamma[\sf \id \cup r^+]}{\Gamma[\sf r^*]} \and
\end{rules}

The following transformations may come in handy but are less straightforward. We will need to prove them. 
\begin{rules}{Extra Rules}
%\inferrule*[left=($+_{\cup}$)]{\Gamma[\sf r^+ \cup s^+]}{\Gamma[\sf (r^+ \cup s^+)^+]} \and nicht invertible
\inferrule*[left=($+^+$)]{\Gamma[\relr^+]}{\Gamma[\relr^{+^+}]} \and
\inferrule*[left=($+_{\cap}$)]{\Gamma[\sf r^+ \cap s^+]}{\Gamma[\sf (r^+ \cap s^+)^+]} \and 
\inferrule*[left=($*_{\cup elim}$)]{\Gamma[\sf (r^*.s^*)^*]}{\Gamma[\sf (r \cup s)^*]} \and
\inferrule*[left=($*_{double}$)]{\Gamma[\sf r^*.r^*]}{\Gamma[\sf r^*]}

\begin{lemma}
Let $\relr \subseteq (E \times E)$ be a relation. $\relr^+ = \relr^{+^+}$ holds.
\end{lemma}
\begin{proof} We use \Cref{def:alttc} for this proof:
\begin{eqnarray*}
\edgein \relr^+ &\Leftrightarrow & \exists n \in \N: \edgein \relr^n \\
&\Leftrightarrow & \exists k \in \N: \exists m_1,\dots m_k \in \N: \sum_{i=1}^k m_k = n \land \edgein \relr^{m_1}.\dots.\relr^{m_k}\\
&\Leftrightarrow & \exists k \in \N: \edgein \relr^{+^k} \\
&\Leftrightarrow & \edgein \relr^{+^+}
\end{eqnarray*}

\end{proof}

\begin{lemma}
Let $\relr,\rels \subseteq (E \times E)$ be relations. Then $\sf r^+ \cap s^+ = (r^+ \cap s^+)^+$ holds. 
\end{lemma}
\begin{proof} The $\impl$ direction is very intuitive and easy to show:
\begin{eqnarray*}
\edgein \relr^+ \cap \rels^+ &\Leftrightarrow & \edgein (\relr^+ \cap \rels^+)^1 \\
&\impl & \exists n \in \N: \edgein (\relr^+ \cap \rels^+)^n \\
%(e,e') \in {\sf r^+ \cap s^+} &\Leftrightarrow & (e,e') \in {\sf r^+} \land (e,e') \in {\sf s^+} \reason{\defof \cap} \\
%&\Leftrightarrow & \exists n \in \N: e=e_1 \land e'=e_n \land \forall i\in [1,n]: (e_i,e_{i+1}) \in \relr \\
%&&\land \exists m \in \N: e=e_1 \land e'=e_m \land \forall i\in [1,m]: (e_i,e_{i+1}) \in \rels \reason{\defof +}\\
%&\Leftrightarrow &  \edgein {\sf (r^+ \cap s^+)} \\
&\Leftrightarrow & (e,e') \in {\sf (r^+ \cap s^+)^+} \reason{\Cref{def:alttc}}
\end{eqnarray*}
For the other direction, we need to prove that $\edgein (\relr^+ \cap \rels^+)^n \impl \edgein (\relr^+ \cap \rels^+)$. 
\begin{eqnarray*}
\edgein (\relr^+ \cap \rels^+)^n &\Leftrightarrow & \exists n\in \N: e=e_1 \land e'=e_n \land \forall i \in [1,n]: (e_i,e_{i+1}) \in \relr^+ \cap \rels^+ \\
& \impl & \forall i \in [1,n]: (e_i,e_{i+1}) \in \relr^+ \land (e_i,e_{i+1}) \in \rels^+ \\
& \impl & \edgein \relr^{+^+} \land \edgein \rels^{+^+} \\
& \Leftrightarrow & \edgein \relr^+ \land \edgein \rels^+ \\
& \Leftrightarrow & \edgein \relr^+ \cap \rels^+
\end{eqnarray*}
\end{proof}


\begin{lemma} Let $\relr,\rels \subseteq (E\times E)$ be relations. Then $\sf (r^*.s^*)^* = (r \cup s)^*$ holds.
\end{lemma}
\begin{proof}
\begin{itemize}
\item[$\subseteq$:] For any $(e_1,e_h) \in \sf (r^*.s^*)^*$ there exist $k,m_1,\dots m_k,n_1,\dots n_k \in \N_0$ with $(e_1,e_h) \in {\sf r}^{m_1}.{\sf s}^{n_1}. \dots {\sf r}^{m_k}.{\sf s}^{n_k}$.
Consequently, there need to be $(e_1,e_{2}),\dots ,(e_{h-1},e_{h})$ where every $(e_i,e_{i+1})$ is either in \textsf{r} or \textsf{s} and $h = \sum_{j=1}^k m_j + n_j$.
Accordingly, $(e_1,e_h)$ is in $\sf (r \cup s)^h$ and thus $(e_1,e_h) \in \sf (r \cup s)^*$.
\item[$\supseteq$:] We can use other transformations to prove this direction.
\begin{eqnarray*}
\sf (r^*.s^*)^* &=& \sf (r^*.s^*)^+ \cup \id \\
&=& \sf ((r^+ \cup \id).(s^+ \cup \id))^+ \cup \id \\
&=& \sf (r^+.s^+ \cup r^+.\id \cup \id.s^+ \cup \id.\id)^+ \cup \id \\
&=& \sf (r^+.s^+ \cup r^+ \cup s^+ \cup \id)^+ \cup \id \\
&\supseteq & \sf (r \cup s)^+ \cup \id \\
&=& \sf (r \cup s)^*
\end{eqnarray*}
\end{itemize}
\end{proof}


\begin{lemma} Let $\relr \subseteq (E\times E)$ be a relation. Then $\sf r^* = r^*.r^*$ holds. \end{lemma}
\begin{proof}
\begin{itemize}
\item[$\subseteq$:] For any $(e,e') \in \sf r^*$ it holds that $(e,e') \in \sf r^*.\id$ and hence $(e,e') \in \sf r^*.r^*$. \\
\item[$\supseteq$:] For any $(e,e') \in \sf r^*.r^*$ there exist $n,m \in \N_0$ with $(e,e') \in {\sf r}^n.\relr^m$. Since ${\sf r}^n.\relr^m$ is the same as $\relr^{n+m}$, it holds that $(e,e') \in {\sf r}^{n+m}$ and therefore $(e,e') \in {\sf r}^*$.
\end{itemize}
\end{proof}

\section{Soundness}\label{sec:soundness}
\begin{theorem}[Soundness]
If there is a proof $\mathcal{P}$ for an inclusion $\relr \subseteq \rels$, then the inclusion holds.
\end{theorem}

\noindent To prove the theorem, soundness of all rules is necessary. Most of the rules can easily be proven through logical implications. For strengthening and weakening, the rules need to be proven with monotonicity of each operator. This follows in the next subsections.
The transformations are proven in the corresponding section or in the appendix. Using the \Cref{lem:implications,lem:bmono,lem:umono}, it is clear that every proof $\prf$ that uses only these rules is sound and therefore the inclusion at the root of $\prf$ holds.

\subsection{Weakening and Strengthening}
To prove the weakening and strengthening rules, we need to prove monotinicity for each operator. Starting with the binary operators, this guarantees that for unification, intersection and concatenation, it holds that replacing a subterm with a stronger one will not weaken the term and replacing a subterm with a weaker one will not strengthen the term.
\begin{lemma}[Binary Monotinicity]\label{lem:bmono} Let $\star: (E\times E) \times (E \times E) \rightarrow (E \times E)$ be any binary operator in rational CAT. It holds that if $\sf r \subseteq s$, then $\sf t \star r \subseteq t \star s$ and $\sf r \star t \subseteq s \star t$ \end{lemma} 
\begin{proof}
For proving monotonicity, the lemma needs to be shown for every binary operator in rational CAT.
We will start with the unification operator:
\begin{eqnarray*}
(e,e') \in \sf t \cup r &\impl & (e,e') \in \relt \lor (e,e') \in \relr \reason{\defof \rel_1 \cup \rel_2} \\
& \impl & (e,e') \in \relt \lor (e,e') \in \sf s \reason{r \subseteq s} \\
&\impl & (e,e') \in \relt \cup \rels \reason{\defof \rel_1 \cup \rel_2}
\end{eqnarray*}
Just as simple as for unification is the proof for intersection:
\begin{eqnarray*}
(e,e') \in \sf t \cap r &\impl & (e,e') \in \relt \land (e,e') \in \relr \reason{\defof \rel_1 \cap \rel_2}\\
& \impl & (e,e') \in \relt \land (e,e') \in \sf s \reason{r \subseteq s} \\
&\impl & (e,e') \in \relt \cap \rels \reason{\defof \rel_1 \cap \rel_2}
\end{eqnarray*}
Since the first two operators were commutative, the order of the relations was not important. As this is not the case for concatenation, there needs to be a distinction between $\sf t.r$ and $\sf r.t$
\begin{eqnarray*}
(e,e'') \in \sf t.r &\impl & (e,e') \in \relt \land (e',e'') \in \relr \reason{\defof \rel_1.\rel_2}\\
& \impl & (e,e') \in \relt \land (e',e'') \in \sf s \reason{r \subseteq s} \\
&\impl & (e,e'') \in \relt.\rels \reason{\defof \rel_1.\rel_2}
\end{eqnarray*}
\begin{eqnarray*}
(e,e'') \in \sf r.t &\impl & (e,e') \in \relr \land (e',e'') \in \relt \reason{\defof \rel_1.\rel_2} \\
& \impl & (e,e') \in \rels \land (e',e'') \in \sf t \reason{r \subseteq s} \\
&\impl & (e,e'') \in \rels.\relt \reason{\defof \rel_1.\rel_2}
\end{eqnarray*}
This proves monotonicity for every binary operator of rational CAT.
\end{proof}
The unary operators of rational CAT are inversion, reflexive closure, transitive closure and reflexive-transitive closure. The next step is to show monotonicity for these aswell.
\begin{lemma}[Unary Monotonicity]\label{lem:umono} Let $f:(E\times E) \rightarrow (E \times E)$ be a unary operator (function) of rational CAT. It holds that for any $\relr,\rels \subseteq E \times E$, if $\sf r \subset s$, then $f(\relr) \subseteq f(\rels)$.
\end{lemma}
\begin{proof}
The first unary operator of rational CAT will be inversion:
\begin{eqnarray*}
(e,e') \in \relr^{-1} &\impl & (e',e) \in \relr \reason{\defof \rel^{-1}}\\
&\impl & (e',e) \in \sf s \reason{\sf r \subseteq s} \\
&\impl & (e,e') \in \rels^{-1} \reason{\defof \rel^{-1}}
\end{eqnarray*}
Next up is the transitive closure:
\begin{eqnarray*}
(e,e') \in \relr^+ &\impl & \exists n \in \N: e=e_1 \land e' = e_n \land \forall i \in [1,n]: (e_i,e_{i+1}) \in \relr \reason{\defof \rel^+} \\
&\impl & \exists n \in \N: e=e_1 \land e' = e_n \land \forall i \in [1,n]: (e_i,e_{i+1}) \in \rels \reason{\sf r \subseteq s} \\
&\impl & (e,e') \in \rels^+ \reason{\defof \rel^+}
\end{eqnarray*}
For the unary operators reflexive closure the monotonicity is given through its definition and \Cref{lem:bmono}:
\[\relr? = \relr \cup \id \subseteq \rels \cup \id = \rels?\]
For the reflexive-transitive closure the monotonicity is given through their definition and the monotonicity of the unification operator and the transitive closure:
\[\relr^* = \relr^+ \cup \id \subseteq \rels^+ \cup \id = \rels^*\]
\end{proof}
With \Cref{lem:bmono,lem:umono} at hand, we can now prove the weakening and strengthening rules.
\begin{itemize}
\item $(\textsc{weak}):~ \Delta[\relr] \subseteq \rels \land {\sf t \subseteq r} \impl \Delta[\relt] \subseteq \rels$
\begin{eqnarray*}
(e,e') \in \Delta[\relt] &\impl & (e,e') \in \Delta[\relr] \reason{\text{\Cref{lem:bmono,lem:umono}, } \sf t \subseteq r} \\
& \impl & (e,e') \in \rels \reason{\Delta[\relr] \subseteq \rels}
\end{eqnarray*}
\item $(\textsc{strength}):~ \relr \subseteq \Delta[s] \land \rels \subseteq \relt \impl \relr \subseteq \Delta[\relt]$
\begin{eqnarray*}
\edgein \relr &\impl & \edgein \Delta[\rels] \reason{\relr \subseteq \Delta[\rels]} \\
&\impl & \edgein \Delta[\relt] \reason{\text{\Cref{lem:bmono,lem:umono}, } \rels \subseteq \relt}
\end{eqnarray*}
\end{itemize}

\section{Completeness}\label{sec:completeness}

\begin{theorem}[Completeness]
For every true inclusion $\relr \subseteq \rels$ of two relational expressions there exists a proof $\mathcal{P}$.
\end{theorem}

To prove the completeness on the rational CAT fragment of this proof system we will transform any proof by Grünke et al. \cite{Gru+26}, where completeness was proven, into one of ours.  
The approach of \cite{Gru+26} transforms an inclusion of the form $\relr \subseteq \rels$ into a logical formula $\phi_{\relr} \land \neg \phi_{\rels}$ where the unsatisfiability of the formula corresponds to the inclusion term being true.
Hence, the Theorem to be proven is this:
\begin{theorem}\label{thm:satinc}
If a RAT-CAT formula $\phi_\relr \land \neg \phi_{\rels}$ is $\mathcal{T}_\Sigma$-unsatisfiable and it exists a RAT-CAT-SAT proof tableau $\pi$, then there exists a relational inclusion proof $\prf_\pi$ for $\sf r \subseteq s$
\end{theorem}
The proof system of Grünke et al. starts with the formula $\phi_{\relr \subseteq \rels} = \phi_\relr \land \neg \phi_\rels$ and transforms it via rules until the tableau is \textit{closed}. 
A closed tableau is one where every branch in it is closed, meaning that every branch is either infinite or contains $\bot_0$. Here, $\bot_0$ means \textit{false} and it appears in a branch if there has been a contradiction. \\ 
The decomposition of the $\phi_\relr$ in \cite{Gru+26} results in a number of properties that events need to fulfill to form an edge in \relr. The negated rules only decompose the the negative part of the formula $\neg \varphi_\rels$ to give predicates that describe the complement of \rels. If there exist events that fulfill all of the predicates, then there exists a counterexample to the inclusion.
Hence, unsatisfiability of the formula is equivalent to the inclusion being true.

Since RAT-CAT-SAT argues directly about events and we do not, we lose some expressiveness in comparison to Grünke et al.. Therefore, we reduce the number of proofs that RAT-CAT-SAT can express to only those that show inclusions between relations.
These inclusions have a standard form as a RAT-CAT formula: An inclusion $\relr \subseteq \rels$ is
\[\phi_{\relr \subseteq \rels} = (e_1.\relr \cap e_2) \neq \emptyset \land \neg((e_1.\rels \cap e_2) \neq \emptyset)\]
We call this the \textit{Relational Inclusion Standard Form (RISF)}.
We prove completeness by showing that every decomposition of $\phi_{\relr \subseteq \rels}$ that results in a proof $\pi$ has an equivalent proof $\prf_\pi$ in our system.

To that end, we put down some properties that $\prf_\pi$ will fulfill:
First, $\prf_\pi$ has the same structure as $\pi$, meaning that whenever $\pi$ uses a branching rule, $\prf_\pi$ also uses one. Secondly, Every branch in $\pi$ that is closed (ending in $\bot_0$ or infinite) has an equivalent branch in $\prf_\pi$ that is closed (ending in \true). The third property is that whenever $\pi$ splits a predicate into two non-atomic predicates, this needs to be reflected in $\prf_\pi$. Finally, if $\pi$ eliminates a relation from the formula, the same must be justified by a rule in $\prf_\pi$.



\begin{lemma}[Branching Lemma]\label{lem:branching}
Whenever $\pi$ creates new branches where the first cubes are $\C^\pi_1, \C^\pi_2$, $\prf_\pi$ can create new branches $\B_1, \B_2$ where when $\C_1$ and $\C_2$ describe counterexamples to the inclusions $\relr_1 \subseteq \rels_1$ and $\relr_2 \subseteq \rels_2$, the terms in $\B_1$ and $\B_2$ need to be exactly those inclusions.
\end{lemma}
\begin{proof}
For unions and Kleene-stars the positive rules create new \textit{branches}. Since all branches need to be closed, this equates to branching in our proof system. To emulate the behavior of $\pi$, the branching in $\prf_\pi$ needs to have the same effect on the semantics.
A union in the positive term essentially means, that a counterexample to the inclusion needs to be in both of the unified relations and to prove the inclusion true it has to be shown that there cannot be a counterexample in either.
This corresponds closely to branching a union in the included term with ($\cup_{L2}$), because it argues that both subrelations need to be included, i.e. there is no counterexample to the induction in either.
For the Kleene-star rule ($*L$) the branching is based on a union too, since $\relr^* = \id \cup \relr^+$. \\
In negative reasoning, branching occurs whenever there is an intersection or a cross product.
For intersections, the ($\cap_2L$) rule parts the decomposition inside of the literal in in two terms that can return the events $f_1,f_2$. Depending on whether this is the outermost operator of that literal, either the ($\neg \cap_1R$) or the ($\neg eL$) rule can be applied. The intuition is, that if both branches end in \false, the counterexample candidate would have to be in both terms and therefore in the intersection. This would mean, that it is no counterexample. If one or both branches cannot be closed, the candidate is only in one term or none and can therefore be a counterexample to the inclusion. \\
In the relational proof, this equates to a term $\relr \subseteq \rels \cap \relt$. Here, we can use the ($\cap_R$) rule, branching the term into $\relr \subseteq \rels$ and $\relr \subseteq \relt$. \\
For the cross product, the ($\neg \times L$) rule creates two branches where each only retains one set. The premise was that the counterexample must not have an edge where the events belong to these sets. The conclusion of the rule is that the first event cannot be in $s_1$ and the second one cannot be in $s_2$. In relational inclusion proofs, we can use the ($\times_R$) rule which branches $\relr \subseteq A \times B$ into $\relr \subseteq A \times E$ and $\relr \subseteq E \times B$. The same goes for ($\neg_1 \times L$) and ($\neg \times_1L$).

Hence, we can use branching in $\prf_\pi$ whenever it occurs in $\pi$ and keep the semantics the same. 
\end{proof}

\begin{lemma}[Splitting Lemma]\label{lem:splitting}
Whenever $\pi$ splits a literal $l$ into the non-atomic literals $l_1, l_2$ (there are only rules that split into two literals), $\prf_\pi$ can justify the separate decomposition of both literals.
\end{lemma}
\begin{proof}
In $\pi$ many rules split a literal into multiple ones. The atomic literals $e_1 = e_2, e \in A, (e,e') \in \relr, e \neq \emptyset$ and their negated counterparts keep information about the relational term that has already been decomposed and are not of concern for this lemma.
We only look at the non-atomic literals where one literal turns into two new ones that take the context of the predicate with it.
Since this only appears in negative reasoning, we can assume that the literal in the premise has the form $\neg p[\dots]$. Furthermore, this gives us the knowledge that only the including term $\rels$ is concerned in $\prf_\pi$. \\
Two literals in the same cube are always connected by a conjunction, meaning that both have to be true in order to fulfill the cube. Seeing that $\pi$ will show the unsatisfiability, the conjunction can be interpreted as two options to create a contradiction. This translates to being two terms that can prove the inclusion $\relr \subseteq \rels$. In relational inclusion proofs the equivalent term would be $\relr \subseteq \rels_1 \cup \rels_2$ where each $\rels_i$ represents one of the literals.
Each term of the unification can be decomposed on it's own.
The rules that split literals all use the unification operator (see ($\neg*L$), ($\neg \cup_2L$), ($\neg\cup_1$)) or duplicate a literal for an equivalent event (see ($\neg A$), ($\neg \equiv L$), ($\neg \top_1$)). In the latter case, this would correspond to a unification with the same term $\rels \cup \rels$. \todo{Verifizieren}
\end{proof}


\subsection{Finite Proofs}
For proving completeness, we will first translate all finite proofs of Grünke et al. into relational inclusion proofs. Finite proofs are those which do not use the Kleene-star rules ($*L$),($*R$),($\neg *L$) and ($\neg *R$) infinitely often. \\
Looking at the rules of Grünke et al., we can observe that any positive literal in RISF will be decomposed by applying rules to the $e_1.\relr$ term. The goal of the decomposition is to get an event $f_1$ for which $(e_1,f_1) \in \relr$ holds. If that point is reached, the ($eL$) rule can be applied, yielding $f=e_2 \land f_1 \neq \emptyset$. \\
The positive rules in \cite{Gru+26} only ever introduce atomic predicates like $e_1 = e_2$ or $e \in \relr$. The decomposition therefore only takes place on one predicate which is never split.



For the negative literals in RISF the same holds for $e_1.\rels$. At the end, the decomposition yields an event $f_2$ with $(e_1,f_2) \in \rels \land \neg (f \cap e_2 \neq \emptyset)$ and after applying ($\neg \cap_e$) we get $(e,f_2) \in \rels \land \neg f_2=e_2$, which would mean that there is no $e_2$ with $(e_1,e_2) \in \rels$. \\
Putting both together, we get
\[(e_1,f_1) \in \relr \land f_1 = e_2 \land f_1 \neq \emptyset \land (e_1,f_2) \in \rels \land \neg (f_2 =e_2)\]
Because both formulas use the same events, we get

\[\exists e_1,f_1: (e_1,f_1) \in \relr \land (e_1,f_1) \notin \rels\]

which is equivalent to the definition of $\semsof{\relr~ \cap~\sim \rels} \neq \0$ which in turn is equivalent to $\semsof{\relr} \nsubseteq \semsof{\rels}$. \\
We will see that any formula $\phi'$ that originates from a formula in RISF can be transformed into a cube that corresponds to the semantics of the relations using only ($aL$) and ($eL$).
We go through all the rules and start with the non-negated ones.


\begin{lemma}[Decomposition Lemma]\label{lem:decomposition}
For any term $e_1.\relt$ in a literal of RAT-CAT-SAT, the decomposition of Grünke et al. \cite{Gru+26} applies only rules which result in either an event constant $f$ which replaces $e_1.\relt$ or a new term $e_1'.\relt'$.
Since this holds in turn for $e_1'.\relt'$, the decomposition will eventually return an event $f$.
\end{lemma} \todo{$\bot_1$ einfügen}

It is important to distinguish the rules of Grünke et al. into those that are applied to the non-negated term and those applied to the negated term. The positive reasoning consists of all rules withour a $\neg$ in their name. The negative reasoning uses the rules with a $\neg$ in the name and those positive rules which are applied to literals, i.e. where the context is $l[\dots]$. 
Furthermore, Grünke et al. assume each term to be union-free and Kleene-star-free. This can be achieved in their proof system by branching the tableau every time a union or Kleene-star occurs in positive reasoning and splitting the predicate into multiple ones in negative reasoning.
As we will see, the ($\cup_{L2}$) and ($+_L$) rules copy the branching and the union operator in the included term can replace the different predicates.

\paragraph{Concatenation} If $\relr = \relr_1.\relr_2$, the ($._{2,2}L$) rule is applied and the result is

\subsubsection{Negative Reasoning}
For \rels{} the rules that Grünke et al. apply are mostly different. If \rels{} cannot be decomposed further, they would apply ($\neg aL$), producing $\neg p[e_1.\rels] \land (e_1,e_3) \in \rels \land \neg p[e_3]$ and if the context is still $(\dots \cap e_2) \neq \emptyset$ then afterwards they use the ($\neg \cap_e$) rule to produce $\neg e_3 = e_2$. \paragraph{Concatenation} If $\rels = \rels_1.\rels_2$, Grünke et al. would again apply the ($._{2,2}L$) rule resulting in $\neg (e_1.\rels_1).\rels_2$. \paragraph{Unification} If $\rels = \rels_1 \cup \rels_2$, the ($\neg \cup_2 L$) rule would be applied, resulting in $\neg p[e_1.\rels_1] \land \neg p[e_1.\rels_2]$. The form required by the decomposition lemma remains. The intuition for the conjunction is that any counterexample must not be in $\rels_1$ and $\rels_2$. Translated into the relational inclusion this corresponds to $\relr$ being a subrelation to $\rels_1$ or $\rels_2$. Since we do not use explicit disjunction but only the unification operator, this equates to distributing the context to both parts of the union. We could therefore use the ($\cap_{\cup dist}$) and ($._{\cup dist}$) rules to make the union the outermost operator.

\paragraph{Intersection} If $\rels=\rels_1 \cap \rels_2$, the ($\cap_2L$) rule can be applied. It creates the term $(e_1.\rels_1) \cap (e_1.\rels_2)$ where the decomposition can continue for both parts of the intersection, since the required form is retained.

\paragraph{Kleene-star} If $\rels = \rels_1^*$, the next rule in $\pi$ would be ($\neg *L$). According to \Cref{lem:splitting} this is equivalent to the new predicates in $\pi$.

\paragraph{Identity} If $\rels=\id$, the next rule in $\pi$ is ($\id L$) which eliminates the \id{} relation, leaving only the event $e_1$ behind. This satisfies the demands of the decomposition lemma.
In $\prf_\pi$, this is the same case as in the positive reasoning. Accordingly we can use ($\id_{conc}$) or no rule at all depending on the context.

As we stated in the paragraph for inversions in positive reasoning, the inversion remains in the term with the edge $(f,e_1)$ and we do not need to apply any rule in our system.

Since the last rule is always going to be one of those we handled in the base case, we look at the first applied rule in any proof of lenth $n$. This could be any of the remaining rules from \cite{Gru+26}. Hence, we need to translate the effects of all of those into our proof system.


Any relational inclusion in \cite{Gru+26} of the form $\relr \subseteq \rels$ can be transformed into the RAT-CAT-SAT formula \[(e_1.\relr \cap e_2) \neq \emptyset \land \neg((e_1.\rels \cap e_2) \neq \emptyset)\]
Grünke et al. decompose the positive term $(e_1.\relr~ \cap e_2) \neq \emptyset$ with the positive rules into the predicates $s \neq \emptyset$, $e_i = e_j$, $e \in A$ and $(e_i,e_j) \in \relr$. Which rules are applied depends on the form of $\relr$. \\

\section{Proof of the Inversion lemma}\label{sec:inversionproof}
\Cref{lem:inversion}:
Let $\relr$ be a relational expression that features an inversion. There is an expression $\relr'$ that only features inversions that are applied to base relations with $\semsof{\relr} = \semsof{\relr'}$. 
\begin{proof}
When it can be shown for each operation in CAT that the inversion of the whole expression can be passed on to the individual terms, any CAT expression has this property. Therefore we show the property for each operation.
\begin{description}
\item[Case $(\relr \cup \rels)^\inv$:] 
\begin{eqnarray*}
\semsof{(\relr \cup \rels)^{-1}} &= &\{(e,e') \mid (e',e) \in \relr \cup \rels\} \reason{\defof \rel^{-1}} \\
&= &\{(e,e') \mid (e',e) \in \relr \lor (e',e) \in \rels\} \reason{\defof \rel_1 \cup \rel_2} \\
&= &\{(e,e') \mid \edgein \relr^{-1} \lor \edgein \rels^\inv\} \reason{\defof \rel^\inv} \\
%= &\semsof{\relr^{-1}} \cup \semsof{\rels^{-1}} \reason{\defof \rel_1 \cup \rel_2} \\
&= &\semsof{\relr^{-1} \cup \rels^{-1}} \reason{\defof \rel_1 \cup \rel_2}
\end{eqnarray*}
\item[Case $(\relr \cap \rels)^\inv$:] 
\begin{eqnarray*}
\semsof{(\relr \cap \rels)^{-1}} &= &\{(e,e') \mid (e',e) \in \relr\cap \rels\} \reason{\defof \rel^\inv}\\
&= &\{(e,e') \mid (e',e) \in \relr \land (e',e) \in \rels\} \reason{\defof \rel_1 \cap \rel_2} \\
&= &\{(e,e') \mid \edgein \relr^\inv \land \edgein \rels^\inv\} \reason{\defof \rel^\inv}\\
&= &\semsof{\relr^{-1} \cap \rels^{-1}} \reason{\defof \rel_1 \cap \rel_2}
\end{eqnarray*}
\item[Case $(\relr.\rels)^\inv$:] 
\begin{eqnarray*}
\semsof{(\relr.\rels)^{-1}} &=& \{(e,e') \mid (e',e) \in (\relr.\rels)\} \reason{\defof \rel^\inv}\\
&=& \{(e,e') \mid \exists e'': (e',e'') \in \relr, (e'',e) \in \rels \} \reason{\defof \rel_1.\rel_2}\\
&=& \{(e,e') \mid \exists e'': (e'',e') \in \relr^{-1}, (e,e'') \in \rels^{-1}\} \reason{\defof \rel^\inv} \\
&=& \semsof{\relr^{-1}.\rels^{-1}} \reason{\defof \rel_1.\rel_2}
\end{eqnarray*}
\item[Case $(\sim \relr)^\inv$:]
\begin{eqnarray*}
\semsof{(\sim \relr)^{-1}} &=& \{(e,e') \mid (e',e) \in~ \sim \relr\} \reason{\defof \rel^\inv} \\
&=& \{(e,e') \mid (e',e) \notin \relr\} \reason{\defof \sim \rel}\\
&=& \{(e,e') \notin \relr^{-1}\} \reason{\defof \rel^\inv}\\
&=& \semsof{\sim (\relr^{-1})} \reason{\defof \sim \rel}
\end{eqnarray*}
\item[Case $(\relr^+)^\inv$:]\begin{eqnarray*}
\semsof{(\relr^+)^{-1}} &=& \{(e,e') \mid (e',e) \in \relr^+\} \reason{\defof \rel^\inv} \\
&=& \{(e,e') \mid \exists n \in \N: e=e_1 \land e'=e_n \land \forall i \in [1,n]:(e_i,e_{i+1}) \in \relr\} \reason{ \rel^+}\\
&=& \{(e,e') \mid \exists n \in \N: e'=e_1 \land e=e_n \land \forall i \in [1,n]:(e_i,e_{i+1}) \in \relr^\inv\} \reason{ \rel^\inv} \\
&=& \semsof{(\relr^{-1})^+} \reason{\defof \rel^+}
\end{eqnarray*}
\item[Case $(\relr?)^\inv$:]\begin{eqnarray*}
\semsof{(\relr?)^{-1}} &=& \{(e,e') \mid (e',e) \in \relr?\} \reason{\defof \rel^\inv} \\
&=& \{(e,e') \mid (e',e) \in \relr \cup \id \} \reason{\defof \rel ?} \\
&=& \{(e,e') \mid \edgein \relr^{-1} \cup \id^{-1}\} \reason{\defof \rel^\inv} \\
&=& \{(e,e') \mid \edgein \relr^{-1} \cup \id\} \reason{\defof \id} \\
&=& \semsof{(\relr^{-1})?} \reason{\defof \rel?}
\end{eqnarray*}
\item[Case $(\relr^*)^\inv$:]\begin{eqnarray*}
\semsof{(\relr^*)^{-1}} &=& \{(e,e') \mid (e',e) \in \id \cup \relr^+\} \reason{\defof \rel^\inv \text{ and } \defof \rel^*}\\
&=& \{(e,e') \mid (e',e) \in \id \lor (e',e) \in \relr^+\} \reason{\defof \rel_1 \cup \rel_2}\\
&=& \{(e,e') \mid \edgein \id^{-1} \lor \edgein (\relr^+)^{-1}\} \reason{\defof \rel^\inv} \\
&=& \{(e,e') \mid \edgein \id \lor \edgein (\relr^{-1})^+ \} \reason{\defof \id \text{ and Case } (\relr^+)^\inv} \\
&=& \{(e,e') \mid \edgein \id \cup (\relr^{-1})^+ \} \reason{\defof \rel_1 \cup \rel_2} \\
&=& \semsof{(\relr^{-1})^*} \reason{\defof \rel^*}
\end{eqnarray*}
\end{description}
\end{proof}
